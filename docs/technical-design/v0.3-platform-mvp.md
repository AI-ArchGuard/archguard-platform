# Platform MVP v0.3 Technical Design

## 目标与边界

Platform 以模块化单体提供 Project、Repository、RuleSet、ScanJob、Result 和 Finding 处置闭环。它只调用 Scanner 公共 CLI，不导入 Scanner Java 类型；不实现源码解析、Git clone、上传、Broker、基线继承或通知。

## 模块边界

- `project` 公开成员鉴权与删除保护 SPI。
- `repository` 保存受控输入根下的规范化相对路径，并拒绝绝对路径、遍历、符号链接和特殊文件。
- `ruleset` 保存不可变 YAML、SHA-256、Scanner/Schema 版本；提交前以独立进程执行 `validate-rules`。
- `scanjob` 以 PostgreSQL 为事实来源，使用 `FOR UPDATE SKIP LOCKED`、租约、attempt token、有限重试和幂等键。
- `finding` 拥有 Result 契约消费快照、语义校验、规范化查询与处置历史。

模块只依赖其他模块的公开接口，不直接读写其他模块的表。Flyway V2 只追加新 schema/table；已发布迁移不修改。

## Scanner Runner

Platform 将 `0.1.0` 请求原子写入共享邮箱。请求只包含任务标识、attempt token、仓库相对路径、规则 YAML 和固定版本，不包含数据库或 OIDC 凭据。Runner 写入报告和状态后，Platform 只接受当前 attempt；迟到或未知结果被丢弃。Deploy 将 Runner 置于 `network_mode: none`、非 root、只读根文件系统和只读源码挂载中。

退出码 `0/2` 分别映射为 `SUCCEEDED/PASS` 与 `SUCCEEDED/VIOLATION`；`64/70`、超时、损坏或契约不匹配映射为 `FAILED`。`70` 的合法部分输出只保存为故障附件，不形成 Finding。

## Result 接受门禁

Platform 使用固定 `0.1.0` JSON Schema 快照验证未知字段、枚举、位置和路径，再校验全局 ID 唯一、引用闭合、Project identity、大小与版本。通过后按原字节保存报告和 SHA-256，并以 job-scoped 稳定 UUID 规范化 Finding/Evidence。

JSON Schema 校验使用与 Scanner 相同的 `com.networknt:json-schema-validator 2.0.7`（Apache-2.0），并排除不需要的 YAML/时间依赖。替代方案是维护第二套手写校验器，但会扩大契约漂移风险。

## 安全与恢复

OIDC 默认只允许 HTTPS；HTTP 仅能同时启用 `oidc,local-compose` profile 和显式开关。Viewer 只读，Maintainer 可注册、扫描、取消和处置；非成员看到 `404`。处置要求原因与期望版本，每次变化写追加历史和审计。

回滚先撤销 Web/Compose 入口，再回退 Platform 应用；V2 迁移保留，不执行 down migration。Scanner `v0.2.1` 向后兼容并可保留。

# 3C Technical Design：不可变基线与 Finding 分类

- 状态：3C 实现候选；以前置 3B 合并后 `main` CI 成功为入口
- 范围：`archguard-platform`；对应 [Issue #20](https://github.com/AI-ArchGuard/archguard-platform/issues/20)
- 运行时契约：[治理基线 API](../../openapi/governance-baselines-v1.json)
- 指纹契约：[3B 设计](v0.4-governance-3b-contracts.md)；固定消费方证据在 Samples `governance/`

## 边界

3C 复用当前已成功的 ScanJob 原始 Scanner Result `0.1.0`、Repository 的 Scanner identity、RuleSetVersion 及 Project 权限。候选的 Git commit SHA 当前是 Maintainer 的认证断言，不证明 Git ancestry；3E 报告提交与 Webhook 才绑定可信 CI 与 PR 最新 head。3C 不接收 Git 凭据、源码，不 clone/fetch，也不执行部分 AST 扫描。Scanner 仍独立且 Schema 不变。

`POST /baselines` 在 `Project + Repository + targetBranch + RuleSetVersion` 比较空间内为成功扫描创建版本；同一空间内重复提升同一 ScanJob 只重新选择原有版本。每次选择追加 `baseline_selections` 及审计记录，增加 `selectionVersion`。版本号、报告 SHA、commit SHA、创建者、创建时间和指纹快照不可修改。活动指针与历史版本分离。只有 Maintainer 可以提升或切换。读取需 Viewer；持久化比较需 Maintainer。

3B 的 `governance-v1.json` 仍为报告提交/门禁的契约目标，不在 3C 冒充已运行。3C 运行时 API 独立记录在 `governance-baselines-v1.json`，3D–3E 按此消费。

## 数据与事务

Flyway V3 新建 `governance` Schema，不修改 V1/V2。`baseline_scopes` 用唯一键隔离比较空间并序列化同空间的版本号与活动选择。`baseline_versions` 和 `baseline_findings` 在同一事务插入并封存；PostgreSQL 触发器阻止封存后再追加、修改或删除。活动指针只能指向同空间已封存版本。`baseline_selections` 是只追加选择史。

比较先记录确切 BaselineVersion，再把已验证成功候选报告计算为 `platform-finding-v1` 快照。集合差得到 `NEW = C-B`、`EXISTING = C∩B`、`RESOLVED = B-C`；冲突载荷或重复逻辑 Finding 失败关闭。`comparisons` 与 `comparison_findings` 在一个事务内写入、封存，并由 `(baselineVersionId,candidateJobId)` 去重。呈现按分类、指纹排序，不依赖 Scanner 数组顺序。重复请求返回同一 Comparison ID；不同活动基线可形成新的历史比较。

版本快照持有逻辑指纹、规范载荷 SHA、Rule、严重性及当次 Scanner Finding ID。后者只用于追溯当次报告，不参与指纹。只在 `NEW`/`EXISTING` 使用候选严重性，`RESOLVED` 取基线严重性；3D 门禁消费这些不可变事实时再评估策略和例外，不改写分类。

## 失败语义、权限及回滚

Project 成员身份在任何资源访问之前校验；Repository、RuleSetVersion 与 ScanJob 必须属于 URL 中 Project 和 Repository。跨 Project 返回隐藏式 `404`，无兼容活动基线返回 `404`，不成功扫描或绑定冲突返回 `409`，无法形成稳定指纹的报告返回 `422`。无基线不会被视为零问题或隐式 `PASS`。写成功后同事务记录主体、Project、动作、目标和 traceId；审计不存报告正文。

发布顺序为 V3 迁移 → Platform 3C 应用 → 后续 3D 门禁；3B 接口保持不变。回滚应用时保留 V3 和不可变历史，不回写迁移；先停用后续 3E/3D 消费，再退回 3C 应用。下一切片只有 3C PR 合并且 Platform `main` 全量 CI 成功才可进入。

验证覆盖固定 Samples 指纹向量、行号与输入顺序扰动、Rule/实体变化、重复/冲突、基线封存与重选、版本隔离、跨 Project 拒绝、V2→V3 升级及空库迁移。本地 Docker 不可用时 PostgreSQL 集成测试须在 PR 和合并后托管 CI 成功，不可仅凭编译通过关闭 3C。

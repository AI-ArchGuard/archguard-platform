# 3E Technical Design：GitHub Webhook 与 CI 门禁闭环

- 范围：Platform、Deploy；对应 [Issue #22](https://github.com/AI-ArchGuard/archguard-platform/issues/22)。
- 前置：3D PR #27 合并且 Platform `main` CI 成功。
- 冻结接口：[3B 报告提交契约](../../openapi/governance-v1.json)；新增 [GitHub Adapter API](../../openapi/governance-github-v1.json)。

## 信任边界

Git Provider 无关的 `GitRevision`、`PullRequestRef` 和 `ReportSubmission` 仍是领域输入；本阶段仅提供 GitHub Adapter。Maintainer 以 GitHub 数字 Repository ID 将一个 Platform Repository 绑定到 GitHub；`owner/name` 只是展示名。Platform 不持有 Git 凭据、不 clone/fetch、不接收源码归档。CI 在自身工作区运行固定 Scanner `v0.2.1`，提交原始 Result `0.1.0` 字节与最小 Git 元数据。提交者的 commit/PR 断言不能单独证明 GitHub 当前 head；只有已验签 Webhook 更新当前 PR head。

GitHub Webhook 使用环境注入的 secret 校验 `X-Hub-Signature-256`，HMAC 比较采用恒定时间。secret 缺失时入口失败关闭。单次消息最大 2 MiB。`X-GitHub-Delivery` 以 UUID 幂等，错误签名不入库；同一 delivery ID 携带不同正文返回冲突。只处理 `pull_request` 的 `opened`、`synchronize`、`reopened`，其他事件验签后标记为忽略。GitHub 没有独立的签名时间戳头，因此使用被签名正文内的 `pull_request.updated_at`，限定在服务器时间 ±10 分钟；超窗消息只留投递事实，不更新 PR。当前 head 以该时间单调推进；同时间不同 head 或更早事件均不覆盖。无法证明 Git ancestry 的边界明确留在已验证事件与签名主体。

## 报告、门禁和恢复

提交先验证 Project/Repository/RuleSetVersion 归属、绑定的 GitHub Repository ID、commit/PR 一致性、固定 Scanner/Schema 版本、50 MiB 大小、UTF-8、原始字节 SHA-256、Schema `0.1.0` 与引用闭合。请求摘要逐行按 3B 固定次序计算；Project 内幂等键与摘要均唯一。相同输入返回原 Submission/ScanJob/Finding/Gate，冲突键返回 `409`。报告导入复用现有 Finding 验证端口，作为已完成 ScanJob 写入；不排入本地 Runner。导入及提交记录处于同一事务，失败无半份可见结果。

提交持久化后调用 3D 门禁并关联确切不可变 GateEvaluation。中途失败保留 `RECEIVED`；CI 以同一键重试可恢复求值。若 PR 当前 head 与报告 commit 相等，才更新当前门禁指针。迟到报告依然可留历史，但不能回退当前 PR。已完成报告早于 Webhook 抵达时，Webhook 会找当前 head 的最新已完成门禁并关联。CI 通过查询 Platform 当前 head 再使用其自身短期 `GITHUB_TOKEN` 发布**该 commit** 的状态；Platform 不接触此令牌。GitHub 外部状态只是展示/检查结果，不是业务事实来源。CI 对最终门禁映射 `PASS→0`、`FAIL→2`、配置 `ERROR→64`、其他 `ERROR→70`；Scanner 自身 `2` 仍需提交报告。

## 版本、部署与回滚

Flyway V5 只新增 GitHub 绑定、Webhook delivery、PR head、报告提交表；已发布 V1–V4 不改写。Repo 绑定和 delivery 在数据库层不可修改，delivery 仅允许一次从 `RECEIVED` 封存。发布顺序是 Platform V5 → Platform 3E 应用 → Deploy CI 模板与 webhook secret 配置 → 3F Web 消费。回滚先停 CI/Webhook 入口及外部状态发布，再回退应用；V5 和审计事实保留，不能 down migration。Web、Scanner 和已冻结 Schema 不变。

验证覆盖空库及 V4→V5 升级、错误签名、重放、ID 碰撞、时间窗口、乱序和迟到、跨 Project、重复报告无重复任务/门禁、CI 引入违规 `2` 与修复 `0`，以及 PR/合并后 `main` CI。没有可达的外部 HTTPS GitHub 入口时，只能用本地签名 Webhook 模拟验收；真实公网投递与最终 Compose 验收在 3H 记录，不假称已发生。

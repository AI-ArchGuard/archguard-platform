# 阶段 3F：治理只读视图

3F 为 Web 提供固定的只读契约，接口见 [`openapi/governance-read-v1.json`](../../openapi/governance-read-v1.json)。既有基线、门禁、例外、提交和单个 PR API 保持不变；不引入迁移，不改变 Scanner Schema。

## 查询语义

- 所有查询先验证调用者在 Project 中有 `VIEWER` 权限，再验证 Repository 归属；跨 Project 和不存在的资源均返回 404。
- 门禁历史须明确 `targetBranch` 和 `ruleSetVersionId`，可以通过 GitHub PR 编号进一步过滤。结果按评估时间和 ID 降序排列；`page` 从 0 开始，`size` 为 1–50，`hasMore` 表示后面还有记录。规则版本必须属于该 Repository。
- 比较详情从不可变比较、基线版本和范围联合查询，输出当时冻结的 `NEW`、`EXISTING`、`RESOLVED` Finding，不重新计算历史。
- PR 列表仅呈现已接收的 GitHub head 与关联的当前门禁 ID。若 `currentGateEvaluationId` 为空，Web 应显示“待评估”，不能把先前提交的 PASS 当作当前提交的结果。
- 趋势由门禁历史的固定计数在 Web 中展示；不同 RuleSetVersion 的历史不得混排。

## 兼容与回滚

先发布 Platform 只读生产者，再由 Web 固定 OpenAPI 快照生成类型并使用接口。回滚时先回滚 Web，再回滚 Platform；由于没有数据库迁移或写入格式变化，旧版 Platform 数据保持可读。现有 3E CI 提交流程不依赖新接口。

# Agent v0.5.0 — 4B 契约冻结（无运行时）

状态：4B 契约草案；以 Docs Feature Spec 和 ADR-0010 为规范来源。机器契约为 `openapi/agent-v1.json` 和 `src/main/resources/contracts/agent-model-output-0.1.0.schema.json`。本切片不注册路由、不调用模型、不建表、不修改 Scanner Schema 0.1.0。

## 边界与版本

- Platform 模块化单体独占请求编排、授权、引用解析和审计；Scanner Finding/Evidence 与报告摘要是事实来源。Agent 结果独立存储，不写回 Finding、Baseline、GateEvaluation 或 CI 退出码。
- 请求绑定 Project、请求者、ScanJob、报告 SHA-256、选中 Finding IDs、不可变 DocumentVersion ID/内容 SHA-256、Prompt 版本、模型配置版本。PR 摘要还绑定 PR head revision ID；服务端锁定具体 model ID、Responses 协议版本、价格目录版本、输入摘要与输出 Schema 0.1.0；客户端不能指定 Prompt、Schema、模型设置、任意提供商或模型。
- `FINDING_EXPLANATION` 恰好一个 Finding 且 PR head revision ID 为 null；`PR_SUMMARY` 为同一扫描和同一已验证 PR head revision 中 1–20 个明确选中的 Finding，PR head revision ID 必填。请求必须在创建前逐项验证同 Project、扫描成功、报告摘要一致、Finding 属于该报告、文档版本已授权；缺失和跨租户对象对外统一不可见。文档版本空数组合法，不能伪造文档依据。
- 当前契约主版本是 `/api/v1`、OpenAPI 0.1.0、模型输出 0.1.0。未来添加必填字段、改变枚举或引用含义须升版本；历史请求仍按当时版本解释。

## 异步与幂等

`POST /api/v1/projects/{projectId}/agent/requests` 需 Project 权限和 `Idempotency-Key`。服务端以 Project、操作者、键为唯一域，对规范化请求计算摘要；相同键和摘要返回同一个请求（包括终态），不同摘要返回 409，不再次计费。不同 Project 不共享键或缓存。提交响应为 202；模型默认关闭或预检额度耗尽时可直接记录 `FAILED`，且不发生外发。

仅允许 `QUEUED → RUNNING → SUCCEEDED|FAILED` 或 `QUEUED → FAILED`。终态不可变，结果与失败互斥；非成功状态结果为 null，非失败状态失败为 null。GET 每次重新执行 Project 授权，不能靠旧 URL 或缓存绕过。重复 worker 领取须用原子状态转换阻止双调用；相同终态不可重写。客户端超时重试只重放同一键，不创建第二笔费用。目标（待 4D 压测）：本地入队 p95 ≤ 500 ms、状态查询 p95 ≤ 300 ms；排队上限 60 s、单次模型调用硬超时 30 s。超时不阻塞扫描/门禁。

## 模型输出和可信引用

模型只接收每次请求临时生成的 `findingRef`、`citationId` 别名及最小合成/授权内容。别名映射保存在 Platform，不包含可由模型选择的真实 URL、Project ID、存储路径或文档版本。模型响应须先按严格 Schema 验证，再作业务校验：`purpose` 与请求一致；所有 findingRef 属于选中集合；所有 citationId 在映射中且被当前 Project 授权；Scanner 引用确属绑定报告中所选 Finding 的 Evidence；文档引用确属绑定的不可变 DocumentVersion 和片段摘要。返回给 Web 的 `VerifiedCitation` 只能由服务端从真实对象构建，不直接复制模型字符串。

`SUPPORTED` 结论必须有非空文本和至少一个已验证引用；每条实质性 claim、ruleBasis 和建议须有适用引用。无法支撑结论时用 `INSUFFICIENT`，不生成事实性结论或未经支撑的建议。证据覆盖 `NONE/PARTIAL/COMPLETE` 按所选 Finding 的已验证 Evidence 覆盖由服务端计算，模型不能自报。建议只允许人工核查或低风险方向，`requiresHumanReview=true`；不得指令修改 PR、代码、RuleSet 或例外。展示层不得把未验证引用渲染为事实。拒绝、截断、非 JSON、未知字段、Schema 或语义不符为 `OUTPUT_INVALID`；引用不存在、版本不匹配或越权为 `CITATION_INVALID`，不做静默丢弃后成功。请求后权限被撤销为 `AUTHORIZATION_REVOKED`。

模型输出 Schema 使用 Responses `text.format` 的严格 JSON Schema 子集：每个对象所有字段必填且 `additionalProperties=false`；空值显式使用 null。提供商的 refusal 与 incomplete 状态在解析前单独检查。结构校验不能替代授权或事实校验。

## 失败、审计、回滚

失败码只描述 Agent；既有扫描和质量门禁继续按确定性规则运行，原 PASS/FAIL 与 CI 退出码不变。审计记录操作者、Project、请求/traceId、各版本绑定、状态变化、失败码、token、延迟、估算费用及请求摘要；不记录凭据、完整源码或原始模型提示词。单请求及 Project 每日预算、输出长度和上下文大小按 ADR-0010 上限预检和计量，超过限额记 `QUOTA_EXHAUSTED`。真实调用验收只用合成证据；CI 用确定性假模型。

兼容顺序：Docs 冻结 → Samples 合成向量 → Platform 契约和契约测试 → 4C 文档管理 → 4D/4E 运行时 → 4F Web → 4G 安全 → 4H 发布。回滚先关闭 Web 入口与模型调用，再回退应用；历史解释和已发布迁移保留。4B 尚无运行时，撤回未发布契约即可。4C 不因本契约自动进入 In Progress。

# Agent v0.5.0 — 4C 项目文档版本与有界检索

状态：4C 实现设计。依据 Docs Feature Spec、ADR-0010 和 4B Agent 契约。本切片不注册 Agent 请求路由、不调用模型、不读取 Scanner 内部表，也不更改 Finding、门禁或 CI。

## 所有权与 API

Platform 模块化单体的 `agentdocument` 模块拥有 `agent_document` Schema。它通过公开的 `ProjectAuthorization` 接口验证当前身份，不读取 Project 模块表。上传只允许 Maintainer，读取和检索允许同 Project Viewer。不可见 Project 与跨 Project 文档版本对外均为 404；可见 Project 中 Viewer 上传为 403。

- `POST /api/v1/projects/{projectId}/documents`：`multipart/form-data` 的 `documentKey` 与 `file`，必需 `Idempotency-Key`。同 Project 同 key/相同规范输入重放原版本；不同输入为 409。相同 `documentKey` 的新幂等键创建下一个不可变版本。返回 201，重放 200。
- `GET /api/v1/projects/{projectId}/documents`：最多 100 条分页元数据；不返回正文。
- `GET /api/v1/projects/{projectId}/documents/{documentId}/versions`：最多 100 条分页版本元数据，按版本号倒序；不返回正文。
- `GET /api/v1/projects/{projectId}/documents/{documentId}/versions/{versionId}`：返回授权的确切不可变版本、正文与片段摘要，供 Maintainer/Web 管理及后续引用解析。
- `POST /api/v1/projects/{projectId}/documents/search`：明确传入 1–10 个互异 `versionIds` 和 2–120 字符的关键词；只返回最多 4 个片段，每片段最多 1024 字符、总计最多 4096 字符。任何越权/不存在版本使整个查询返回 404，不做部分成功。

上传只接受声明为 `text/markdown` (`.md`/`.markdown`) 或 `text/plain` (`.txt`) 的文件；原始字节上限 262144，必须是严格 UTF-8、非空、无 NUL/不允许的控制字符，不允许超过 128 个非空段落。拒绝 URL、压缩包、二进制、文件路径和 Git 凭据形式的输入；不保存客户端文件名。文档 key 限制为 3–63 字符的小写 ASCII slug。内容 SHA-256 按原始字节计算；文本不执行任何指令，检索不触发网络或模型调用。

正文按原始顺序分为最多 256 个、每个最多 1024 UTF-16 字符的稳定片段；不切开 surrogate pair。保存片段序号、起始字符偏移与 UTF-8 片段 SHA-256。4D 必须再次验证版本归属和片段摘要，并在其独立 Token 预算内进一步截断；本接口返回值仅是候选数据，绝非 Prompt 指令或可信引用。

## 持久化与并发

V8 仅追加 `agent_document.upload_requests`、`documents`、`document_versions`、`document_fragments`。版本和片段有拒绝 UPDATE/DELETE 的数据库触发器；应用没有删除 API，历史引用不因新版本失效。Project 删除由文档模块的公开删除守卫和数据库 FK 双重阻止，不级联清除历史版本。上传在应用事务中先占有 `(project_id, idempotency_key)` 的唯一槽，再锁定对应文档行分配连续版本号；数据库唯一约束处理并发冲突。审计仅写 Project、操作者、版本 ID、SHA、字节/片段计数和 traceId，不写正文/文件名。

## 兼容与回滚

4B 契约已经合并；本切片只增加 API 与 V8，不改其 Agent 请求/输出 Schema。4D 可依赖不可变 `DocumentVersion` 与片段摘要，Web 在 4F 消费文档 API。回滚先关闭尚未启用的 Web/模型入口，再回退 Platform 应用；V8 和历史文档保留，不修改或执行旧迁移的 down migration。4C PR CI 与合并后 Platform `main` CI 成功后才能启动 4D。

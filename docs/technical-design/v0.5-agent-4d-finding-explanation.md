# Agent v0.5.0 — 4D 单 Finding 解释

状态：合成路径实现；真实提供方调用等待 ADR-0010 的数据处理、凭据、地区、模型和价格目录审批。此设计以 Docs Feature Spec、ADR-0010、4B 契约和 4C 文档版本设计为边界。

## 请求与事实边界

用户显式 `POST /api/v1/projects/{projectId}/agent/requests`，只接受 `FINDING_EXPLANATION`、恰好一个 Finding、`prHeadRevisionId=null` 和至多十个不可变文档版本。先通过 Project 当前成员授权，再核对已完成的 ScanJob、报告 SHA、同 Project Finding 及文档版本。跨 Project 对象统一不可见。GET 重新检查当前 Project 授权。接口使用 4B 的 Agent OpenAPI 0.1.0，不改 Scanner Result/Rules 0.1.0。

Agent 模块仅通过 `ProjectAuthorization`、`ScanJobOperations`、`FindingOperations` 和 `DocumentOperations` 的公开接口读事实；不读取它们的表或写回确定性结果。4D 在这些接口上增加按 ID 的获授权读取，以及异步任务用的指定操作者成员复核。候选引用从已关联 Evidence 和 4C 有界检索片段生成请求内随机别名。模型输入只含规则、规范消息、逻辑实体、Evidence 类型/行号和获授权片段；不含内部 ID、完整报告、源码、完整文档或其他 Project 数据。文档文本仅作为数据字段。

## 状态、额度和输出

V9 追加 `agent.requests` 和 `agent.budget_usage`；不修改已发布迁移。Project/请求者/幂等键唯一约束与输入 digest 在并发下只创建一个请求。提交后异步领取，数据库原子 `QUEUED→RUNNING` 阻止重复模型调用；终态及绑定由触发器保护。队列超过 60 秒失败，单次调用默认硬超时 30 秒且只允许下调，无自动重试。超时或不确定的提供方故障保留当日预留额度，避免未知费用被再次消费。

合成价格目录按每输入 Token 1 µUSD、每输出 Token 2 µUSD 预留；输入以 JSON UTF-8 字节数作保守上界，单次限制 8,000 输入/1,500 输出 Token、0.10 美元，Project 每 UTC 日 5 美元、部署每 UTC 日 20 美元。两级额度行在同一事务内按固定顺序锁定和预留，已知实际费用结算，未知费用保持预留。该合成目录不能作为真实提供方价格；真实适配器接入前须批准并实现版本化真实价格目录、包含指令/Schema 开销的 Token 估算与外发前拦截。

提供方原始输出先经过严格 4B JSON Schema、未知字段拒绝，再检查 purpose、Finding 别名、每条事实/规则依据/建议的引用、引用映射的 Project/报告/文档版本、人工审核标志及低风险建议边界。成功结果只使用服务端重建的 `VerifiedCitation`；证据覆盖由 Evidence 引用数计算。无法支撑的响应只能产生 `INSUFFICIENT`，不得将自由文本作为事实。拒绝、超时、无效输出/引用及额度耗尽保留稳定失败码；原始响应不持久化或返回。审计只记版本、摘要、状态、Token、延迟、费用和 traceId，不记密钥、正文或原始响应。

## 安全开关、验收与回滚

运行时默认 `ARCHGUARD_AGENT_ENABLED=false`，生产只装配禁用模型端口；显式开启但无获批适配器时直接 `MODEL_UNAVAILABLE`，无网络外发。本切片还强制端口声明 `syntheticOnly=true` 才能执行；真实适配器不能借用合成价格目录绕过审批。CI 注入确定性假模型，覆盖有效 Evidence/文档引用、注入文本作为数据、并发幂等、跨 Project、非法引用/Schema、超时、额度、终态不可变和原 Finding/扫描状态不变。尚未接入 OpenAI Responses API；真实调用必须等 ADR-0010 审批，且只用合成证据验收。

兼容顺序为 Docs/4B 契约 → Platform 4C 文档版本 → 本 4D 解释 → 4E 摘要 → 4F Web → 4H Deploy。回滚先关闭 Web 入口和模型调用，再回退 Platform 应用；V9、历史请求、额度和审计保留，不做 down migration。4D 相关 PR 合并且 Platform `main` CI 成功前，不启动 4E。

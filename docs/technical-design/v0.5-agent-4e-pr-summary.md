# Agent v0.5.0 — 4E 已选 Finding 的 PR 摘要

状态：仅合成模型路径；真实 DeepSeek 外发仍关闭，单独等待账户级书面审批。沿用 Docs Feature Spec、ADR-0010/0011 与 4B 契约，不更改 Scanner 契约。

## 输入与事实绑定

Project Viewer 显式提交 `PR_SUMMARY`、成功 ScanJob 与报告 SHA-256、1–20 个互异且属于同一扫描的 Finding、已应用的 `prHeadRevisionId`，以及至多十个获授权的不可变文档版本。Platform 通过治理模块公开接口确认该 PR head 的仓库、PR 标识、分支和 commit 与已完成的报告提交一致，且该提交对应所选扫描及报告摘要；不接受任意 webhook delivery 或仅有未完成报告的修订。异步调用前和保存结果前再次核对请求者的 Project 成员资格及 PR/报告绑定。旧修订仍可按版本追溯，不声称是当前最新 head。

输入摘要对选中 Finding 和文档版本排序后计算；同一 Project、请求者、幂等键的同输入重放同一请求，异输入返回冲突。摘要独立绑定 `pr-summary-0.1.0` Prompt、输出 Schema、模型配置、价格目录和 traceId；旧 `FINDING_EXPLANATION` 摘要算法保持不变。模型只见请求内随机 Finding/Evidence/文档引用别名、规则和规范消息、证据类型及行号、获授权的有界文档片段，不见内部 ID、完整源码或报告。Agent 通过 Finding、Document 和 Governance 的公开应用接口读事实，不直接访问其他领域表。

## 输出与安全边界

异步状态、原子领取、额度预留、30 秒上限、超时失败、审计和不可变终态沿用 4D。仅接受严格 4B 输出 Schema：`SUPPORTED` 结论须有每个所选 Finding 的 Evidence 引用；每个所选 Finding 都须有分别引用其自身 Evidence 的事实主张和规则依据。建议只能指向所选 Finding，且每个被指向的 Finding 须有相应 Evidence；跨 Finding 冒用 Evidence、未知/越权引用、无效 Schema 或声称已执行修改均失败。可选的文档引用必须映射到绑定的不可变版本和片段，不能代替 Scanner Evidence。服务端只返回重新构造的可验证引用，原始模型文本不留存。结果是建议，不反写 Finding、例外、RuleSet、PR 或门禁，Agent 故障不改变原有 `PASS`/`FAIL`。

4E 使用 V10 Agent 专属迁移仅扩展请求目的约束；V9 与主迁移 V1–V8 不改写。CI 用确定性假模型验证授权、引用隔离、幂等、迁移升级及 4D 回归。生产默认关闭；显式启用但未装配获批适配器时仍为 `MODEL_UNAVAILABLE`，不会外发。真实模型调用和客户数据外发不属于本切片。

兼容顺序：Docs/4B 冻结 → Platform 4C/4D → 本 4E → Web 4F → Deploy 4H。回滚先关闭 Web 入口和 Agent 调用，再回退应用；保留 V9/V10 已发布迁移和历史请求，不执行 down migration。仅当 4E PR 合并且 Platform `main` CI 成功，才推进 4F。

# Agent v0.5 — 个人批次执行只读视图

状态：实现及本地回归完成，PR/main CI 尚待；基于 Platform #62 合并提交 `361fc2816e79f3d606d2f6186ad2d11a6d381ab6`，其 PR 和 main 的 governance、Maven 与容器构建均成功。不部署、不读取运行 Secret、不调用模型或账户，不构成阶段退出证据。

## 目标和范围

Web 刷新或丢失 live POST 响应后，必须从服务器恢复已经分配的 request ID，而不是换幂等键或根据浏览器内存判断可以补发。依据 Docs ADR-0013/0014 与[受控 runtime](v0.5-agent-personal-live-runtime.md)，只增加 `GET /api/v1/projects/{projectId}/agent/batches/{batchId}/execution`。原 Batch GET、批准/撤销及 live POST 不变；没有新的写能力、迁移、依赖、数据外发字段或模型协议。

本接口只解释 ADR-0014 context 策略批次。旧策略可能有多请求历史，不能虚构唯一槽位；访问新视图返回稳定 409，旧元数据 GET 保持可读。不升级或修改旧批次。

## 权限与投影

应用服务先验证当前 Project Viewer，再检查 Agent schema，最后按精确 Project/batch 读取。不以 request 创建者代替当前授权，不因默认关闭、期限已过、撤销或凭据换删而隐藏历史。GET 不检查 Key、来源文件、网络或发送准入，也不写成功审计、费用或修复记录。现有过滤器覆盖所有响应的 no-store，包括匿名 401 和错误。

公共 DTO 分开返回 batch 元数据、成本策略、当前保留/已结算金额及尝试数、可空 stop、按解释→摘要排序的两个固定模板。每个模板分别有可空的已分配 request 与 attempt；attempt 的 outcome 可空。只投影已有的状态、固定失败类别、traceId、时间、可信 usage 和本地计价，不返回输入、候选引用正文、Prompt、幂等键、凭据版本/Key、来源证明、检查引用或 provider 原文。引用和结果仍经原 Request GET 的当前 Project 授权读取。

## 快照与状态语义

持久层使用一条有界 SELECT，在同一个 PostgreSQL MVCC 语句快照内读取 immutable manifest、V16 slot、精确 V14 link、request、attempt/outcome、stop 和 usage。不能复用含 FOR UPDATE 或 INSERT 的账本锁方法。缺失 usage、非法 manifest、slot/link/request 不一致、错误 attempt 绑定或非法结算形态明确返回脱敏 503，不能默认为空或零费用。

- request 为空只表示该快照没有已提交槽位，不排除并发提交，不是允许补发。
- request 已存在而 attempt 为空时，模板槽位仍永久占用，不能创建替代请求。
- attempt 存在而 outcome 为空时，费用仍保留；不能自动改成 UNKNOWN 或宣称零费用。
- UNKNOWN 是不可变未知，保留原预留；SETTLED 仅表示可信费用已独立结算，不等于结果或引用成功。
- FAILED 不等于未发送、未收费或可重试；没有 stop 也不是继续调用许可。

observedAt 是数据库观察时间，不是发送许可或乐观版本锁。该视图不能证明供应商收到请求次数、确切发送时刻、供应商账单、worker 存活或当前 Secret/网络有效性，因此不提供 sentCount、retryAllowed、canCall 或“可用剩余次数”。摘要的必要串行条件仍是解释 SUCCEEDED 且对应 outcome SETTLED，真实 POST 始终执行原有全部新鲜检查。

# Agent v0.5 — 个人上下文费用策略与两次合成验收边界

状态：Issue #43 的默认关闭增量实现；依据已合并且 Docs main CI 成功的 [ADR-0014](https://github.com/AI-ArchGuard/archguard-docs/blob/main/adr/0014-personal-token-admission-and-cost-reservation.md)。本切片只增加新策略/契约、持久化绑定和离线测试；不装配真实出口、调度或 Web 真实请求，不部署、不调用模型/账户/余额、不产生真实费用，也不关闭 #43、4H 或阶段 4。

## 范围与不变条件

仍使用个人所有者本地部署、DeepSeek 官方固定 `https://api.deepseek.com/responses`、`deepseek-flash`、受限 Responses HTTPS/JSON：无会话、工具、流式或自动重试，思考关闭，输出最多 1,500 Token。Platform 保持模块化单体，无新依赖；最小外发、三次资源授权、严格输出/引用、凭据版本、网络限制和审计保持。Scanner Schema、Agent Output 0.1.0 和确定性扫描/门禁不变。

完整请求体仍先校验不超过 6,000 UTF-8 字节，包括 instructions、input、JSON Schema 与控制字段。字节数不是输入 Token 证明；新策略把输入 8,000 改为调用后验收阈值，不引入预发送 Token 计数保证。所有者仅有条件批准解释/摘要各一次、串行最多两次，单次 USD 0.35、合计 USD 0.70；工程/CI 及具体 Project/manifest/来源/模板/凭据版本/有效期等运行绑定仍是前置条件。输入 Key、确认风险或批准批次本身不打开出口。

## 新旧策略与公共契约

- 旧确认 [0.2.0](../../contracts/agent-personal-enablement-0.2.0.schema.json)继续精确绑定旧 `deepseek-v4.1-flash-2026-10-06` 映射与 `deepseek-flash-peak-usd-2026-10-06`。旧批次 [0.1.0](../../contracts/agent-live-batch-0.1.0.schema.json)仅适用该旧策略，不因当前配置或相同模型别名自动升级。
- 新确认 [0.3.0](../../contracts/agent-personal-enablement-0.3.0.schema.json)精确绑定 `deepseek-v4.1-flash-2026-10-15` 与新 `deepseek-flash-context-peak-usd-2026-10-15`；同一 DTO 的字段形状不变。混合 schema/映射/价格版本、缺失未知风险/撤销条件、无效来源/期限或凭据版本仍拒绝。旧 schema 文件及已有批准原文不改写。
- 新批次 [0.2.0](../../contracts/agent-live-batch-0.2.0.schema.json)仍只有原八个字段，**没有 schemaVersion 或调用者可选策略字段**。必须恰好两个不同模板、maxRequests=2、maxCostMicrousd 在 **632,746–700,000** 之间。服务端按已保存、不可变的 enablement 选策略，再验证相应请求形状；`oneOf` 只是文档中的允许形状，不允许调用者通过金额切换旧批准的授权含义。
- 新策略只接受一个 FINDING_EXPLANATION 与一个 PR_SUMMARY 模板；模板所绑定 Project、资源/输入/候选引用与受控合成来源的 digest 必须匹配。重复用途、缺少任一用途、额外模板、旧确认配新预算、新确认配旧预算均拒绝。
- [设置/确认 API](../../openapi/agent-enablement-v1.json)及[批次 API](../../openapi/agent-batches-v1.json)提升为 0.2.0，POST 分别接受旧/新 schema 的 oneOf，响应兼容读取两类历史元数据。身份/Origin 在 8 KiB 严格解析前验证，未知/重复字段和类型转换不放宽；no-store 及无 Secret/原始正文返回保持。Settings.modelCallsAvailable 固定 false，无新增 send/reserve/settle HTTP 接口。

## 费用依据与算法

2026-10-16 再核对的[官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)、[模型列表说明](https://api-docs.deepseek.com/api/list-models/)及[Responses 参数](https://api-docs.deepseek.com/api/create-response/)与 ADR-0014 冻结依据一致：模型别名映射、输入加输出总上下文 1,048,576，以及高峰每百万 Token 未命中输入 USD 0.30、命中 USD 0.006、输出 USD 1.20。检查仅访问公开文档，没有查询账户或实际模型 API；该示例/声明不是对托管隐藏包装的证明。

新预留保守地把全部 1,048,576 上下文当作未命中输入，另加 1,500 输出而不扣减上下文：316,372.8 microUSD 向上取整为 **316,373**。两次预留合计 **632,746**，低于授权总额 **700,000**；单请求本地准入最多 **350,000**。Project 每 UTC 日 5,000,000、部署每 UTC 日 20,000,000 microUSD 不变；旧值可下调，不得因新策略上调日额度。

`LiveCostPolicy.VERSION`、`RESERVATION` 和原默认 cost 保留旧 4,200 语义；新增独立上下文版本及显式按版本选择的预留/计价。新 usage 校验允许超过 8,000 的输入被可信计价，但仍检查非负整数、总量一致、缓存不超过输入、reasoning=0、输出及冻结上下文依据；输出业务合法性和 8,000 验收阈值不替代费用事实。金额运算使用有界整数、明确溢出保护，完成一次向上取整；目录未知、过期或绑定不符失败关闭。

这仅是本地事务准入和基于供应商声明的保守预留，**不是供应商账户强制限费或绝对零超支保证**。模型/价格/上下文依据变化或实际用量异常时停止并重新评审；不使用缓存命中、低峰或余额推测缩小预留。

## 持久化与策略绑定

仅追加 Agent **V15**，在 `agent.live_batches` 加不可变 `cost_policy_version NOT NULL DEFAULT 'deepseek-flash-peak-usd-2026-10-06'`。默认值明确标记旧行原有策略，不升级旧批准、输入、预留、attempt 或结果；历史内容不改写，不修改 V1–V14。新批次必须由服务端显式写入新策略版本，读取直接使用批次已存版本，不依赖当前选中的确认记录推断政策。

批准/创建/预留和发送前复核要求批次、关联的不可变启用记录、request 绑定及 attempt 的版本一致；禁止将旧批次换成当前新确认来获得新授权。模型/Prompt/价格及 digest 仍进入不可变请求/关联。后续 settings 或 Key 变更只使未来准入失效，不能改写已存版本。

attempt 已有不可变 `price_version` 与 `reserved_microusd`；结算始终按 **attempt 自己的版本**和原 UTC 日处理，不按当前设置或新版默认值。旧请求维持旧 usage/4,200 逻辑，新请求使用 316,373；读取、幂等重放及晚到结算不能隐式跨策略迁移。UNKNOWN/SETTLED 终态保持不可变，未知结果保留原策略预留。

## 串行、停止与独立费用

锁序仍为 Project settings → batch usage → deployment UTC-day budget → Project UTC-day budget；预留、唯一 attempt 与成功审计原子提交。新策略禁止以不同 request ID 重用同一模板产生补偿尝试；费用释放不会恢复尝试次数或允许新增模板。

固定按解释先、摘要后的顺序：首次只能解释模板获得新 attempt；第二个摘要模板必须在同一批次锁下看到前一个解释 request 已 **SUCCEEDED 且 outcome=SETTLED**，才能新预留。前一 RUNNING/QUEUED、FAILED、没有结果、没有结算或 UNKNOWN 都不能放行。仅 usage 结算但输出/引用还未成功，不能抢跑第二次；并发竞争必须由实际持久化状态和锁序拒绝，而不是 Web 按钮或内存计数。

新策略输入超过 8,000 时，先独立结算可信已发生费用，再将该请求标为明确失败，阻止后续批次发送；不把超阈值当作免费或 UNKNOWN 的理由。输出/引用失败、授权撤销、Key 删除、请求恢复终结或结果保存失败同样不撤销可信费用。网络/用量未知则 UNKNOWN 并保留 316,373，不退款、不自动重试或补齐第二次。

V15 的 `agent.live_batch_stops` 只追加一次，复合外键绑定同 Project、批次和持久化请求关联，代码只允许稳定类别。超阈值或 UNKNOWN 的结算与停批在同一独立清理事务提交；其他执行失败先独立停批再写失败终态，不能因失败结果/审计落库迟到开放第二次。停批不会释放次数或改写原预留/已知费用，重复停止不改变首个原因。

领取 CAS 只接受两组精确 profile/catalog 配对并核对不可变批次策略，拒绝跨版本混搭。新策略的领取边界必须显式提供停批账本和有界清理；旧兼容构造器在 CAS 前拒绝新策略。只有已提交的 opaque claim 所有者可在预留前的准备/资源失败后停批并写失败，禁止用新幂等键补齐；并发输家不能据此停止真正执行者。外部失败码仍用 `OUTPUT_INVALID`，超阈值的停批原因 `INPUT_TOKEN_LIMIT` 与可信 usage 独立保留供审计核对。

保留[数据库期限](v0.5-agent-database-deadlines.md)及[有界凭据消费](v0.5-agent-bounded-credential-wait.md)的原剩余期限和独立有限清理；不以费用新策略声称已解决共享池获取、网络提交、文件/ACL 等全部硬取消限制。费用/失败记录晚到时仍可独立持久化，不重新开放发送。

生产装配仍缺少不可变运行许可：领取后、attempt 前若进程崩溃，停批可能尚未持久化；仅扫描 attempt 不能证明新 request ID 不是补发。下一切片须把两次已创建的精确 request ID 连同 Project/batch/template/manifest/凭据及有效期绑定在受控许可中，并在领取/核心/发送前核验（或采用仅新策略的每模板唯一请求约束）。不自动生成替代 ID，不把当前停批逻辑说成已覆盖该崩溃窗口；未补齐前真实出口继续关闭。

## 测试与验证

- 先冻结新 schema/策略正反测试：旧合法输入保持，新版本精确匹配，混合版本、额外字段、风险缺失、期限/来源/Key 元数据错误均拒绝；两个 DTO 的字段保持兼容，旧 schema 未改。
- 新批次边界：恰好两个唯一模板、两个固定用途、费用 632,746/700,000 边界；旧/新确认与预算互串拒绝，API oneOf 与历史元数据兼容，Settings 继续不可用。
- 计价包含输入 8,000/8,001/上下文边界、输出/缓存/总量/reasoning、整数溢出、取整、新旧版本及 UNKNOWN 保留；不是只修改某个输入断言。
- 真实临时 PostgreSQL 验证 V14→V15 保留旧数据/不可变触发器、重复 migrate 零变化、新批次策略列、旧结算及新串行顺序；RUNNING、已结算但未成功、FAILED、UNKNOWN、重复/并发及换确认不能创建第二次或额外 attempt。
- 核心假响应验证超阈值已知费用先结算再失败/停批，原有输出/引用/费用/权限断言保留；默认准入仍拒绝，网络调用为零。先最小测试，再完整 verify、PR CI 和合并后 main CI，不用文档声称未运行结果。

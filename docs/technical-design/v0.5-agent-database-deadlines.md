# Agent v0.5 — 数据库等待与独立清理边界

范围：把原执行期限接入真实核心的数据库读取、预留/发送前复核和结果保存，补齐可复现的 PostgreSQL 取消与恢复证据。没有模型调用、真实出口装配、Web、运行配置、迁移、依赖或公共 REST/Schema 变化。Platform 仍为 0.4.0，Scanner、合成 worker 和门禁不变。

## 模型期限与数据库范围

模型 HTTP 调用继续使用原单调执行期限的剩余时间，最多 30 秒，并由已有传输层取消。数据库限制不是另给每一步 30 秒，也不是“任意操作系统 I/O 均能在第 30 秒强杀”的承诺。取得连接、JDBC/服务器网络故障和提交回执丢失必须与 SQL/锁等待分开描述。

内部 `LiveDatabaseWork` 端口只有数据库事务和独立清理两种操作，默认拒绝，不接受 HTTP 或明文凭据消费回调。核心首次查请求、RUNNING 复核及完整资源授权分别进入只读事务；账本只使用新增有界入口。旧无界入口不能作为有界入口的回退。核心入口及最终发送前拒绝已有事务/同步作用域，避免 `REQUIRES_NEW` 返回后恢复调用方外层事务，使 HTTP 意外跨事务。

`JdbcLiveDatabaseWork` 每次创建独立 `REQUIRES_NEW` 事务定义，验证事务管理器与实际 DataSource 属于同一连接域。取得连接后再次验证原 supplier，并设置本事务 PostgreSQL `lock_timeout` 和 `statement_timeout`，均不允许 0（0 意味禁用）；锁等待预算约为语句预算的一半，最少 1 毫秒且不大于语句预算，为回滚留出余量。Spring 查询超时作为额外防护，不能代替原单调时钟检查。配置只使用 `SET LOCAL`，提交/回滚和连接复用后不得泄漏。

预算在首次读取 supplier 前记录本地单调起点，取原剩余值和初始值减去实际耗时的较小者。常量或增大的 supplier 不能续期；最多 30 秒，零/负值、线程中断、异常或非法预算失败关闭。动作返回后、原结果 CAS 后、审计后和提交前继续检查期限。

不能在外部包一层有界事务后调用账本原 `REQUIRES_NEW` 入口：内层会换连接并丢失 PostgreSQL LOCAL 设置。预留/复核抽取共同业务体，有界入口直接在新端口事务中执行；兼容入口保留原调用方式。结果的 `finishBounded` 同样直接保存 CAS 和审计，不能嵌套原结果事务。

## 已发生费用与失败恢复

合法 usage 仍先结算，再拒绝迟到/无效的业务结果。`settle`、`unknown`、有界拒绝审计和 `failBounded` 使用独立 5 秒清理预算，不继承已过期的发送期限，也没有 ThreadLocal 期限可被 `REQUIRES_NEW` 意外继承。仅清理阶段可暂时清除旧中断标志以尝试持久化，finally 恢复旧/新中断；新中断仍使清理事务失败回滚。它不重开 HTTP、重新授权调用或自动退款。

关闭 Project、撤销成员/启用记录、删除 Key、恢复终结请求或跨 UTC 日不能抹去已产生费用。清理失败保留原预留，模型不重试；恢复重放只能核对持久化状态，不重新发送。数据库提交回执丢失可能导致结果不确定，应保守保留账本并核对历史，不能宣称所有提交异常都已回滚。

超时、中断、PostgreSQL `57014`/`55P03` 转为无 cause 的 `MODEL_TIMEOUT`。未知 SQL/连接/配置错误转为稳定不可用；已知业务错误只保留类别，去除原 cause/suppressed，不把 SQL、路径或私密正文带到调用者。

## 连接池与明确限制

Spring 在事务回调之前取得连接，因此事务 timeout 不能限制此前全部池等待。此实现不并发改写共享 Hikari `connectionTimeout`，也不以 Future 超时丢弃迟到连接或费用回复。连接获取仍受现有池配置约束；如果归还/取得连接时原期限已过，业务 action 为零并回滚。部署最终验收须核对实际有限池等待、连接/网络参数与故障恢复，不把本切片说成精确的全链路 30 秒退出保证。

本切片没有新增连接级 network timeout；不声称已经证明网络黑洞下的提交/回执取消。文件、ACL、加密和同步领域非 SQL 工作也不能因此宣称可强杀。dispatcher 的领取及失败补写仍是兼容事务路径，不属于本切片有界覆盖。生产装配及最终候选仍需按这些明确边界完成故障注入、关闭出口和回滚恢复。

## 验证

回归先复现核心误用仅支持旧无界账本的实现，再修改调用链。真实临时 PostgreSQL 测试在锁持有者不释放的情况下观察 `pg_blocking_pids`，验证设置/预算/结果行锁确实取消、预留/结果/审计回滚、已结算费用保留；用长语句验证服务器取消和连接可复用。独立小池测试证明 LOCAL 配置不泄漏、连接迟到后零 action、清理中断恢复和安全错误。

固定时钟的账本/结果夹具使用独立临时数据库，与其他缓存 Spring 上下文的后台恢复隔离；不关闭生产恢复逻辑、不降低状态或费用断言。核心测试保留原幂等、权限、结果和费用断言，并显式验证 HTTP 期间无事务。先最小相关集，再完整 Wrapper verify、PR CI 和合并后 main CI；本文件不是阶段验收报告。

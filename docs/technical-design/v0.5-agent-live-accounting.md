## 批次与来源证明

内部 `LiveAccountingOperations` 和[Batch Input 0.1.0](../../contracts/agent-live-batch-0.1.0.schema.json)仅供后续受控编排消费，不是新的 REST API。Owner + Project Maintainer 及现有凭据管理 Origin/传输约束适用于批准/撤销；读取和预览需要 Project Viewer。服务端生成批次 ID、批准人和时间；要求有效的个人确认及当前加密凭据版本，最多 24 小时且不得晚于确认/价格有效期。

清单绑定 1–20 个已有不可变请求输入快照。服务器排序模板 ID，固定用途、scan/report、PR 修订、所选 Finding ID、文档版本/摘要、输出 Schema 和实际输入/候选引用摘要。只移除输入的 promptVersion，真实 Prompt 独立绑定；正文、数据和不透明引用句柄全部保持固定，不在批次或审计复制输入内容。旧失败/合成请求只用作模板，不被改写为真实请求。

调用者提供的 manifestSha256 必须等于服务器计算值，但这只能证明一致性，不能证明内容确为合成。必须另经 `SyntheticBatchInventory` 对 Project、受控 inventory ID 和精确 digest 核对；字符串声明、复选框、API Key 或风险确认不能代替来源证明。生产 `ClosedSyntheticBatchInventory` 永远 false；真实批准清单的受控文件、内容核验、配置/部署与 HTTP 管理入口留给后续切片，不能直接替换为 always-true。

批准另有显式 callsApproved=true、次数 1–20 与费用上限 4,200–84,000 microUSD，且费用不超过次数乘以 4,200。每次批准形成独立、不可变记录，不自动创建请求/尝试；撤销追加事件且幂等，不删除历史。已有 Project 删除守卫通过确认历史阻止关联批次被删除。

## 一次尝试与事务锁序

内部 reserve 仅为后续已经提交的 RUNNING 请求记账。请求者身份必须匹配且当前为 Project Viewer；部署/Project 开关、当前选中确认、部署 ID、凭据版本、批次有效期/撤销/清单核对全部重新检查。请求必须为独立 deepseek-personal-0.1.0 模型绑定，固定模型/协议/价格/真实 Prompt，并精确匹配模板资源、数据、引用和包含批次/确认/凭据版本的 input digest。不能把旧假模型请求算作真实请求或放宽 syntheticOnly 防护。

所有变更使用应用层 TransactionTemplate 的 REQUIRES_NEW：请求必须已提交，预留/结算和成功审计独立原子提交，审计失败全部回滚；失败审计在业务回滚后独立提交，审计不可用不返回成功。禁止在同一外层事务未提交请求时调用 reserve；后续 worker 接线须遵守此顺序并传播经校验的 actor/trace 上下文。

锁序固定为 Project settings → batch usage → deployment UTC-day budget → Project UTC-day budget。批准、撤销与预留首先锁相同 settings，防止并发失效检查绕过；跨 Project 通过部署日额度行锁串行化。三层预留及唯一 attempt 一起提交。以 request_id 唯一约束防重复：重放相同批次/模板返回原 attempt 且 newAttempt=false；不同绑定冲突，不再增加次数或费用。

newAttempt=true **仅表示新记账，不是网络通行证**。本切片不验证编码后 6,000 字节/输入 Token 上界、固定网络出口、第三次资源授权或输出引用，也不提供实际发送执行器。后续编排仍须在外发前完成资源/最小投影/Token/网络准入与真实端口校验；仅调用本接口不能授权外发。

## 费用、未知结果与结算

复用冻结的 2026-10-06 高峰美元快照：输入未命中/命中/输出为每百万 Token USD 0.30/0.006/1.20；不是本轮查询到的当前价格或供应商账单。真实启用前必须重新核对官方目录，变化须新版本与独立决策，不静默沿用。

8,000 输入、1,500 输出且全部未命中时每次预留 4,200 microUSD。Project/部署每 UTC 日硬上限为 5,000,000/20,000,000，可通过内部配置下调到 0，不得上调；负值或超硬上限时记账失败关闭，不在启动阶段阻断核心模块。批次同时约束 spent+reserved 和尝试总数，结算释放差额不能恢复次数。

真实与旧假模型日账本分表，避免把合成费用记成真实费用。实际结算校验输入/输出/缓存/总 Token 及 reasoning=0，以已预留的目录计算并只向上舍入一次；缓存命中大于输入、Token 超限/缺失、总量不一致或目录不匹配均记 UNKNOWN，既不持久化异常原值也不释放预留。有效用量即使后来输出/引用失败也应结算，不以结果失败退款。

UNKNOWN 是不可变终态；随后重复提交有效用量也不能重新结算或释放额度。SETTLED 同样只记录一次。网络超时/断连及崩溃后保留预留，不自动重试或退款；崩溃可能留下尚无 outcome 的 attempt，其预留仍计入限额，后续恢复接线不能据此重发。这里没有新的定时恢复任务。

关闭开关、撤销批准、移除 Project 成员、删除 Key 或跨 UTC 午夜不会抹去已发生费用：结算只允许原请求者的内部上下文，以原 attempt 的部署/日期记账，不依赖当前调用授权。由于没有外部结算入口，这不开放越权查询或写入能力。供应商延迟、实际账单核对与模型响应追溯留在后续适配器/真实验收中。

## 持久化、验证与兼容

独立 Agent V12 追加六表：批次、批次额度、批次撤销、真实日账本、attempt、outcome；使用同 Project 外键和原请求唯一键。批次/撤销/attempt/outcome 数据库拒绝 UPDATE/DELETE；额度计数仅在事务内更新。保留 V1–V11，不改变原请求状态/结果或主迁移链。记录模型请求关联、确认/凭据/设置版本、UTC 日、预估/实际费用与合法用量；审计无 Key、Prompt、原始输出或文档正文。

# Agent v0.5 — 独立领取与可信调度基础

范围：承接 ADR-0010/0011/0012/0013 与 V14 请求关联。本切片仅交付**未装配、默认拒绝调度**的内部基础及假执行回归，不是可用的真实模型入口。不修改公共 REST/OpenAPI、Scanner Schema、旧迁移、凭据格式、依赖或运行中的 Compose。Platform 仍为 0.4.0；#43、4H 和阶段总 Issue 保持开放。

## 可信身份和 trace

`AuthenticatedTaskScope.capture(expectedRequester, operation)` 只接受当前已认证的 OIDC JWT，比较已验证 subject、认证名称与持久化 requester 的 UUID，并拒绝缺失/过期 exp。只捕获不可变 UUID、权限名及 exp，不保留 Jwt、Bearer Token、原 Authentication、SecurityContext 或浏览器请求。它是可信进程内延续，不接受调用者提供身份或权限，也不是对恶意 JVM 内部代码的沙箱。

任务单次使用，执行入口复查 exp，以新的空 SecurityContext 安装私有认证，finally 恢复旧 context。私有任务认证不能再派生 capture；`requireActive()` 在开始新动作时复查到期。**身份读取不等于新动作授权**：到期后身份仍可用于结算已发生费用和失败清理，不能因 Token 到期丢弃合法 usage。Project 角色从当前业务授权接口重新核对，不把捕获的权限当作永不撤销的 Project 授权。

`TraceTaskScope` 只接受持久化请求的 32 位小写十六进制 traceId；执行期间清空无关 MDC，只安装该 trace，finally 恢复完整旧映射。队列任务只持有 ID、身份事实和 trace，不捕获输入正文、JWT 或 Key。

## 独立领取与事务

`LiveRequestStore.claim` 是独立于 synthetic claim 的单条 CAS：只把匹配 requester、Project、完整不可变 Link 以及固定 live 模型/协议/价格/Schema/用途/Prompt 的 QUEUED 请求改为 RUNNING。无关联 live、伪装 synthetic、错误版本、其他 Project、终态和重复领取均不成功。这个 CAS **仅建立处理所有权，不代表允许发送**；不读取设置/费用表，不创建 attempt 或预留。

未注册的 `LiveDispatchTransitions` 在 REQUIRES_NEW 中检查当前身份、新动作有效性、Project Viewer、持久化 trace 和 60 秒队列期限，执行 CAS 并原子记录脱敏 running 审计。行锁等待后、审计后及提交前重新检查期限和身份；失效或审计失败回滚领取。领取事务提交后才调用 core，不能在持有请求行锁时进入设置 → 批次 → 费用的锁序。

未注册的 `LiveRequestDispatcher.dispatch(project, request)` 验证当前调用者为持久化 requester，捕获上述作用域；有实际事务时只在 afterCommit 排队，回滚不排队；无事务时请求须已可读取。它没有轮询、自动重试或 HTTP 创建入口。外层回滚不会撤销之前 REQUIRES_NEW 已提交的创建记录，遗留 QUEUED 请求仍由原恢复流程明确终结。

只有成功提交领取的胜者进入执行核心或保存失败。Claim 只由事务边界私有签发，限定同一实例使用，不能由调用者构造；字符串表示隐藏快照内容。重复任务返回无领取，不改写原执行者。执行器拒绝只返回稳定不可用，不终结可能已排队/运行的另一副本。同步/异步未知异常转换为稳定类别；日志不记录原 message、cause、输入或响应。领取/失败持久化不可用时保留原状态交给恢复，不退款、不重试。完整真实执行仍由已有 reserve/checkBeforeSend、资源复核、单次 attempt、独立费用结算和严格输出/引用校验负责。

## 默认关闭与尚未解除的关卡

dispatcher 的公开构造器始终拒绝 dispatch；只有同包测试可注入假准入/执行函数，没有允许生产调度的配置或 Bean。真实 core 公开构造器仍拒绝出口；创建服务没有调度回调，现有执行器和 Web 不接线，`modelCallsAvailable` 仍为 false。

生产装配必须另外提供专用有界执行器及生命周期、发送前 `requireActive()` 与执行能力期限、完整输入 Token 依据、硬取消和网络准入。队列 60 秒检查或 Future.cancel 不构成全链路 30 秒硬取消：凭据 monitor/文件读取、JDBC 连接/锁/语句/提交仍缺执行级有界取消证据；本切片不改变这些机制。取消也不证明提供方停止处理或撤销费用。

2026-10-15 公开资料核对未发现冻结的 [Responses 协议](https://api-docs.deepseek.com/api/create-response/)及[模型/高峰价格目录](https://api-docs.deepseek.com/quick_start/pricing/)变化，但[官方 Token 说明](https://api-docs.deepseek.com/quick_start/token_usage/)仍只给近似估算及调用后 usage。未找到覆盖 instructions、input、JSON Schema 和隐藏包装的受支持预发送计数/上界依据；固定 [recipe README](https://github.com/deepseek-ai/deepseek-recipe/blob/8cadfede7063c896b944e7bae05daa3549ae97ea/README.md)不支持 JSON Schema 约束。不能以 6,000 字节、离线 tokenizer 或调用后拒绝冒充 ≤8,000 输入 Token 的证明。需要取得依据或另立明确残余风险决策后，才可能解除该关卡；本轮不改变协议、预算或 ADR。

## 验证与兼容

- OIDC 缺失/伪造/过期/requester 不符、Token 不进入新 context、单次与并发重放拒绝、拒绝延续派生、线程及 MDC 正常/异常恢复。
- 专用 claim 两用途、错误 Link/绑定/输入、无关联/伪装/终态、并发唯一胜者，原 synthetic 正例保留；无 attempt 或预算副作用。
- afterCommit/rollback、拒绝排队、作用域拒绝、失败前/后所有权与脱敏；领取与审计原子回滚、行锁等待后过期、失败幂等及未装配断言。
- 最小相关测试后完整 verify，并核对 PR CI；合并后须核对对应 main CI，不把测试夹具或公开协议核对记为真实模型验收。

兼容顺序仍为 Docs 冻结语义 → Platform 内部基础 → 后续提供方接口 → Web → Deploy。本轮无公开契约/迁移/配置升级，消费者无需同步；不部署、不执行任何模型/账户请求。回滚先关闭入口/出口再回退应用，保留 V14、凭据、批准、请求、费用和审计历史，不改写已发布迁移。

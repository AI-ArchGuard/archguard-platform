# Agent v0.5 — 默认关闭的真实响应执行核心

范围：在已提交、已领取的 `RUNNING` 请求上实现内部执行核心，串接受控批次账本、固定 Responses 客户端、资源复核、费用结算和输出校验。**不是 Web 可发起的真实请求功能**：本切片不提供请求创建/调度路由、不读取运行时凭据、不注册真实客户端/worker、不修改 Scanner Schema、公开 OpenAPI、迁移或运行中 Compose。Platform 仍为 0.4.0，无新依赖。原 syntheticOnly 模型和假费用路径不变。

## 准入、调用与身份

执行核心只读取服务端已保存的快照，并要求当前可信认证操作者等于原请求者。公开构造器始终使用拒绝发送策略；仅同包测试源码能够注入确定性准入与时钟 seam，没有环境变量、HTTP 参数或生产允许实现。后续异步接线须单独实现原请求者/trace 的受控作用域与清理，不能继承浏览器线程或采用自报身份。

处理顺序：严格构建有界完整请求 → Token/出口准入 → 公开领域 API 资源复核 → 独立事务预留 → `newAttempt=true` 唯一执行者 → 锁后重新核验批次、批准、凭据版本、证明和 UTC 日 → 再次资源/准入/请求状态检查 → 按批准版本消费凭据的回调 → 最后检查 → 唯一 HTTP POST。重放/并发看到已有 attempt 直接返回；取得唯一 attempt 前的失败只抛出稳定错误，不能终结共享请求或写费用/结果审计。未来创建/调度层必须另行处理尚未取得 attempt 的请求恢复，不以重放者终结原执行者代替。

初始核心只有凭据消费接口。[后续版本绑定消费基础](v0.5-agent-version-bound-credentials.md)提供当前槽位的内部可信回调；不返回明文、不回退环境/旧版本，也不注册真实客户端。执行核心对 preflight 和最终发送分别做一次约束。**不得在持有凭据存储锁时进入设置行锁**：现有账本锁序为设置 → 凭据状态，最新领域/账本/请求复核改在 preflight 锁外完成；锁内最终回调只做期限/CAS/传输。生产硬取消、可信调度与出口准入仍是独立接线关卡，不因此开放出口。

`LiveResourceAuthorizer` 通过公开 Project、ScanJob、Finding、Document、ReportSubmission 接口核对真实扫描/报告、所选 Finding/Evidence、文档版本/摘要/有界片段与 PR 修订。模板候选本身不等于真实资源或当前授权。调用前至少两次、结果保存前再复核；未来创建服务也必须复用该检查。

默认单一单调时钟检查 30 秒期限；传给 HTTP 的是剩余时间，不再重置 30 秒。已有有界 HTTP 实现负责网络取消。准备、资源/账本调用返回后、凭据回调和发送前均复核；迟到但可信的 usage 仍先结算。成功结果事务在 CAS 行锁等待后、审计后和提交前再次检查，超时检查失败回滚结果及其审计，独立费用保留。任意来源已终结的请求不能被覆盖。

**这不是 30 秒内结束全部操作的硬取消保证**：同步公共领域 API、JDBC 连接/行锁等待和提交尚未设置执行级取消期限；检查只能在这些操作返回或进入事务回调时执行，提交本身仍可能等待。生产装配前必须验证连接/锁/语句超时、取消回收与恢复，不以假时钟测试代替。`providerLatencyMs` 只记录发送到响应返回的观察区间；`latencyMs` 记录调用开始到结果处理/最后资源检查结束的观察区间，不宣称包含最终数据库提交。生产 worker 的队列期限、可信身份/trace 作用域及恢复接线也尚未实现。

## 费用和不可信输出

可信 envelope/模型/usage 的解析独立于业务输出。保留原严格 decode 行为；真实客户端可返回 `OUTPUT_INVALID` 及合法 usage，不保留/展示非法原文。非 JSON 对象、拒答或错误业务结构不能把已知费用变成 UNKNOWN。未知 envelope/模型/usage、HTTP/超时失败保守 UNKNOWN，保留预留，不退款、不重试。

合法用量先通过真实账本独立事务结算，再做本地完整 Schema、引用、低风险建议校验与保存前资源复核。业务输出/引用无效、撤权、请求恢复终结或结果审计失败不撤销已结算费用。结果与结果审计在独立事务内保存，CAS 只修改 RUNNING；没有假预算结算。日志/异常/审计不含凭据、原始请求/响应或文档正文。客户端拒绝回显当前 Key 或已知凭据前缀的 responseId，避免这些字段变成追溯/审计出口；该拒绝按未知记账保留预留，不保存不可信元数据。

客户端也对解析后的 JSON 字符串值与字段名做当前 Key 的精确匹配（包括 Unicode 转义后回显），命中即清空业务文本并返回 OUTPUT_INVALID，**保留合法 usage 和安全追溯 ID**供独立结算。普通凭据前缀不等于当前 Key，不据此拒绝业务文本。这个防御不证明对拆分、变形编码或历史 Key 的全面 DLP，也不允许模型看到 Key 作为提示输入。

## 尚未解除的真实出口关卡

6,000 UTF-8 字节上限不是完整请求 ≤8,000 输入 Token 的证明。2026-10-11 核对的[官方 Token 说明](https://api-docs.deepseek.com/quick_start/token_usage/)给的是近似字符比例，响应 usage 是调用后数值；公开 API 未列出受支持且覆盖完整 Responses 包装的预发送计数能力。[固定参考库](https://github.com/deepseek-ai/deepseek-recipe/blob/8cadfede7063c896b944e7bae05daa3549ae97ea/README.md)明确未支持 JSON Schema 约束，不能据其证明托管请求的包装一致。本地 tokenizer 可以不部署模型，但不足以补足该服务端依据。因此默认准入仍拒绝：须取得完整包装依据，或由明确 ADR 调整准入及残余风险语义，不能静默改变协议。

本轮公开协议核对未发现冻结的 [Responses 接口](https://api-docs.deepseek.com/api/create-response/)、`deepseek-flash` → `DeepSeek-V4.1-Flash` 映射或[高峰价格](https://api-docs.deepseek.com/quick_start/pricing/)变化（USD/百万 Token：未命中输入 0.30、命中输入 0.006、输出 1.20）。此核对不是账户费用批准，也不是不可见服务端行为的证明。

本轮仅假 HTTP/合成数据回归，没有账户余额查询、真实模型请求或收费。Web 新 Key 不等于批次费用批准。版本绑定凭据消费基础已追加，但桥接未装配；后续依次：补齐持久化 batch/template 请求关联与专用调度、生产硬取消/准入/网络检查 → Web 受控入口 → 单独获批合成真实验收 → Deploy 发布和唯一阶段报告。#43、4H 与阶段总 Issue 保持打开。

## 兼容与回滚

Docs ADR-0011/0012/0013 → Platform 真实账本/批次/本内部核心 → 后续公开提供方接口 → Web → Deploy。旧请求、幂等键、扫描 PASS/FAIL 和既有迁移不变。回滚先关闭 Web 入口和模型出口再回退应用，保留历史批准/请求/费用/审计；本切片不变更运行中的部署。

## 1. 问题与范围

普通解释/摘要通过 `AgentApplicationService` 已能生成获授权的 `AgentSnapshot`，但仅走 synthetic/disabled 模型。真实链的 `live_request_links`、`live_attempts`、模板槽和 `PersonalLivePolicy` 都要求合成 batch/template；V11 的个人确认与当前输入 0.4.0 又严格要求 `SYNTHETIC_ACCEPTANCE`。因此不能把旧开关打开、改一个枚举或伪造 batch/template ID 来支持日常 Project。

本增量只解决：已配置个人所有者从普通页面选择一个 Finding 请求解释，或选择同一可信 PR 修订/扫描中的 Finding 请求摘要。后台固定最小来源快照，在独立、有界、可撤销的日常授权下经现有官方适配器执行。单体和现有模块边界保持；不增加模型、协议、源码字段、工具、自动重试、通用聊天、SDK、数据库或新依赖。

设计批准不批准花费。当前日常 `maxAttempts`、`maxCostMicrousd`、`expiresAt` 均 **UNAPPROVED**；默认开关 false、没有 grant、没有默认金额/次数/有效期。本文测试值只能用于合成数据与假 HTTP。

## 2. 冻结的不变量与设计选择

1. 旧普通 API、enablement/settings 0.4.0、live API 0.1.0、batch API 0.3.0 及 Agent Output 0.1.0 保持原契约。新增独立 Daily API 0.1.0，不往旧响应加入旧严格客户端可能拒绝的新字段；旧 `SYNTHETIC_ACCEPTANCE` 记录永不授权日常发送。
2. 日常风险接受、累计花费/次数授权、Project 开关、部署技术开关分别留存。设置流程可一次串联这些动作；服务器提供版本/凭据/部署和检查事实，浏览器转交返回 ID，用户不手填工程 ID。
3. 所有日常操作只允许配置 owner。解释需当前 Viewer；摘要需当前 Maintainer；风险、grant、启停、撤销需 owner + Maintainer。读取请求、列表、引用需 owner + 当前 Viewer，摘要资源复核仍需 Maintainer。
4. `agent.requests` 继续保存不可变输入、候选、绑定及终态。日常仅新增授权/关联/费用事实，不再造一套请求或结果表。
5. 一个请求最多一个 attempt；领取、预留和 HTTP 不是同一件事。相同键恢复同一请求；明确重复一次已成功的 Finding 操作可以使用新键创建新逻辑请求，消耗新次数和预留。失败/UNKNOWN 后原 grant 停止，换键不能恢复。
6. 每个 grant 同时只允许一个未终结日常请求（设计选择）。创建时占逻辑槽，成功结果和可信费用都完成后才释放；结算费用本身不释放槽。没有“解释先于摘要”的日常模板依赖。这样一条失败不会与同 grant 的下一次发送竞跑。
7. 费用共享现有 `agent.live_budget_usage` 的部署/Project/原始 UTC 日行；绝不使用 fake 的 `agent.budget_usage`。该表只有金额，现有 `Usage.attempts()` 对日额读取为 0，不能拿它限制日常次数。次数来自新的 grant 累计计数，跨 UTC 日不清零。
8. 完整编码 JSON ≤6,000 UTF-8 字节，输出 ≤1,500 Token，输入 8,000 是调用后停发阈值。保守预留 316,373 microUSD；单次技术准入 ≤350,000，Project/部署 UTC 日技术上限 ≤5,000,000/20,000,000 microUSD，可下调。它们都不是所有者批准金额。
9. 继续固定 `deepseek-flash`、映射 `DeepSeek-V4.1-Flash-1017`、`responses-v1-restricted`、价格 `deepseek-flash-context-peak-usd-2026-10-15`、当前解释/摘要 Prompt 与 Output 0.1.0。没有扩大响应白名单。

ADR-0016把精确DTO/数据库约束/状态与实现选择交给Platform维护。本文新增的生产者内部选择为：同grant单个活动逻辑请求、7天技术天花板与固定binding digest、独立Daily API 0.1.0、V17/V18分层，以及下文窄lease/association和单一资源所有者。这些细化不扩大已批准的用户、用途、材料、技术费用上限或模型能力；没有新的所有者花费授权，也不另设通用工作流或审批框架。独立评审应核对这些选择的兼容性和可实现性。

## 3. 系统绑定与风险事实

新增同 Agent 模块的 `DailyRuntimePolicy`，以当前配置和 `CredentialVersionSource` 的元数据构造 `DailyBindingSnapshot`。它不读 Key、不联网、不探测余额/账户。必须满足既有 local-compose + oidc、可信 owner/deployment、凭据管理、JVM 禁重试/TLS 防护、固定官方 HTTPS、有限数据库等待、非 synthetic 运行装配；共用技术防护提取为 `PersonalRuntimeSafety`，保留原 `PersonalLivePolicy.requireBatch` 的合成专用语义。

新增配置 `archguard.agent.daily.enabled=false`、`runtime-revision`（已部署固定兼容组合及非敏感配置的 64 位小写 SHA-256）、`secret-check-ref`、`network-check-ref` 及非敏感 `evidence` 结构。日常不要求配置 synthetic Project/batch；Project 由单独设置/grant 限定。`runtime-revision`、检查引用和 evidence 由部署操作员提供，页面只展示，不让用户反复填写。缺项/格式错/过期即不可用，不由应用启动或页面打开伪造检查。

`DailyBindingSnapshot` 的确切字段：`deploymentId:UUID`、`ownerId:UUID`、`runtimeRevision:sha256`、`credentialVersion:UUID`、`modelAlias:string`、`mappingSnapshot:string`、`allowedResponseModels:string[1]`、`modelProtocolVersion:string`、`explanationPromptVersion:string`、`summaryPromptVersion:string`、`outputSchemaVersion:string`、`priceCatalogVersion:string`、`dataPolicyVersion:"personal-selected-nonsensitive-0.1.0"`、`secretCheckRef:ref`、`networkCheckRef:ref`、`evidence:DailyEvidence`。`ref` 与旧策略一致：`[A-Za-z0-9][A-Za-z0-9._:-]{0,127}`，不以 `sk-` 开头。

`DailyEvidence` 为 `sources:Source[5]`、`priceCatalogExpiresAt:Instant`。Source 为 `kind,url,version,checkedAt`；kind/固定 URL 直接复用 `PersonalEnablementPolicy` 的 TERMS、PRIVACY、CACHE、MODEL_PRICE、PROTOCOL 五项，不接收任意 URL；version 使用 ref，checkedAt 是操作员真实核对事实，必须不晚于 now 且不早于 now−7天。不得复制旧确认的 checkedAt 或把当前读取时间当供应商核对时间。证据最大年龄/风险有效期 7 天只是沿用的技术天花板，不能填成所有者已同意的使用期限。

`runtimeBindingDigest` 是上述完整结构按字段固定顺序、sources 按 kind 排序的 JSON UTF-8 SHA-256；不含当前时间、可用状态或设置修订。将该结构原样持久化于风险接受记录，保留后续差异依据。任一字段变更都使旧 ack/grant 不能新发送。真实发送前仍须当前官方依据和相关 PR/main CI/具体部署验证；此机制不声称配置字符串能自动证明外部条件。

## 4. 新公开契约：Daily API 0.1.0

任务 1 已新增 `openapi/agent-daily-v1.json`（OpenAPI 3.1.0，info.version=0.1.0）、`contracts/agent-personal-daily-{risk,grant,request}-0.1.0.schema.json`、Java DTO/操作接口及合成 fixtures。结构契约不代替后续服务的跨字段、授权、时间、额度及事务校验，也未注册路由或运行时。

所有路径前缀为 `/api/v1/projects/{projectId}/agent/daily`。所有 JSON 对象 `additionalProperties:false`，拒绝重复键、尾随内容、标量强制转换；先授权后读正文，正文最多8,192字节，UUID/小写64位SHA-256/RFC3339时刻严格解析。日期使用 UTC 秒级规范化；数组不接受 null/重复值。响应与错误 `Cache-Control:no-store`，设置响应带 `ETag:"<revision>"`。新增过滤器只覆盖 daily 路由。字段的 null 只用于下文明确的未配置/未产生事实。

### 4.1 获取上下文与设置

`GET /context` → 200 `DailyContext`：

```text
{ schemaVersion:"0.1.0", runtimeBinding:DailyBindingSnapshot|null,
  runtimeBindingDigest:sha256|null, unknowns:string[8],
  limits:{reservationMicrousd:316373, perRequestMicrousd:350000,
          projectDayMicrousd:integer, deploymentDayMicrousd:integer,
          maxEvidenceAgeSeconds:604800, maxRiskAgeSeconds:604800},
  settings:DailySettings, currentGrant:DailyGrantView|null,
  runtimeReady:boolean, unavailableReason:DailyUnavailableReason|null }
```

unknowns 精确复用旧八项 PROCESSING_REGION、STORAGE_REGION、TRAINING、HUMAN_REVIEW、LOG_RETENTION、CACHE_ISOLATION、CACHE_RETENTION、SUBPROCESSORS。未配置时 context 仍可读，binding/digest 为 null，runtimeReady=false；没有预算建议值。`runtimeReady` 仅是本地必要条件，不等于 Key 有效、账户余额、供应商可用或发送许可。

`GET /settings` → 200 `DailySettings={enabled:boolean,revision:int64>=0,grantId:UUID|null,modelCallsAvailable:boolean,unavailableReason:DailyUnavailableReason|null}`。

`PUT /settings`，必须 `If-Match:"<revision>"`，正文 `{schemaVersion:"0.1.0",enabled:boolean,grantId:UUID|null}` →200 DailySettings。enabled=true 必须绑定当前有效 grant；false 必须 grantId=null。持锁比较修订，成功递增1；同一值再次提交仍按旧 API 一致的成功更新规则递增。没有有效授权不允许启用；启用本身不调用模型。

DailyUnavailableReason 的固定集合及优先级：`PROJECT_DISABLED`、`DEPLOYMENT_DISABLED`、`RUNTIME_NOT_READY`、`RISK_ACK_REQUIRED`、`RISK_ACK_REVOKED`、`RISK_ACK_EXPIRED`、`GRANT_REQUIRED`、`GRANT_REVOKED`、`GRANT_STOPPED`、`GRANT_EXPIRED`、`CREDENTIAL_CHANGED`、`BINDING_CHANGED`、`EVIDENCE_EXPIRED`、`GRANT_EXHAUSTED`。不把供应商状态塞进这里。当前 grant 的显示包含原始状态；可用性按上述第一条实际适用原因失败关闭。

### 4.2 风险接受

`POST /risk-acknowledgements`，必须 `Idempotency-Key`，正文：

```text
{schemaVersion:"0.1.0",runtimeBindingDigest:sha256,expiresAt:Instant,
 sourcesReviewed:true,riskAccepted:true,materialRightsAccepted:true}
```

来源和版本由 context 提供；用户显式确认已审阅展示的固定来源、残余未知风险及本人选材权利。布尔值必须 true，不预勾。服务器 `acknowledgedAt` 只表示这一动作，不表示操作员 source.checkedAt，二者均保留。expiresAt 必须由所有者选择，`now < expiresAt <= min(now+7天,各source.checkedAt+7天,priceCatalogExpiresAt)`，无默认值。digest 必须与当前 binding 一致。

201/重放200 `DailyRiskView={id,projectId,ownerId,acknowledgedAt,expiresAt,runtimeBindingDigest,credentialVersion,dataPolicyVersion,revokedAt:Instant|null}`；Location 指向 `GET /risk-acknowledgements/{id}`。原始完整 binding 和风险确认保存在后端，不公开 Key。`POST /risk-acknowledgements/{id}/revoke` 只接受空正文，幂等200，追加撤销并关闭关联的日常设置；不撤销旧 synthetic enablement。

### 4.3 有界费用授权

`POST /grants`，必须 `Idempotency-Key`，正文：

```text
{schemaVersion:"0.1.0",riskAcknowledgementId:UUID,runtimeBindingDigest:sha256,
 allowedPurposes:["FINDING_EXPLANATION"|"PR_SUMMARY"],
 maxAttempts:integer,maxCostMicrousd:integer,expiresAt:Instant,callsApproved:true}
```

purposes 为非空唯一集合，只含这两项；maxAttempts 严格为 `1..2147483647`，maxCostMicrousd 为 `316373..maxAttempts*350000`（类型/技术边界，非建议次数或金额；乘法用 long）。有效授权累计金额始终为 `reserved+spent<=maxCost`，不因日切换重置；实际可发次数可能因保守预留更少。expiresAt 必须 `now<expiresAt<=risk.expiresAt` 并受当前证据/价格期限约束。必须当前 owner/project/deployment/credential/digest 匹配，不能从旧 synthetic ack 推导。

201/重放200 `DailyGrantView={id,projectId,ownerId,riskAcknowledgementId,runtimeBindingDigest,credentialVersion,allowedPurposes,maxAttempts,maxCostMicrousd,approvedAt,expiresAt,state,revokedAt:Instant|null,stop:DailyStop|null,usage:{attempts:int32,reservedMicrousd:int64,spentMicrousd:int64,activeRequestId:UUID|null}}`。state 为 `ACTIVE|REVOKED|STOPPED|EXPIRED|EXHAUSTED`，优先 REVOKED、STOPPED、EXPIRED、EXHAUSTED、ACTIVE；ACTIVE 仍须通过 Project/运行条件检查。DailyStop 为 `{requestId:UUID,code:string,createdAt:Instant}`，code 复用既有 live stop codes。EXHAUSTED 包含次数用尽或金额不足一次预留；activeRequestId 存在不等于 EXHAUSTED。

`GET /grants/{id}` 和空正文 `POST /grants/{id}/revoke` →200同视图；撤销追加事实，关闭当前选中设置、递增修订，保留在途与费用。新的 grant 不自动替换设置、不继承旧余额、不清除旧 attempt/UNKNOWN；旧累计次数保留。授权缺失的日常开发和默认部署不得创建真实 grant。

风险/grant 的幂等键与请求键均为原约束（1..128个可见ASCII字符）。风险、grant 各有独立 `(project,owner,key)` 唯一域；同键不同原输入摘要409。重放不制造第二次批准，过期/撤销后重放返回历史200并显示状态，绝不延长。创建类接口只首次201，重放200。

### 4.4 请求与恢复

`POST /requests`，必须 `Idempotency-Key`，正文：

```text
{schemaVersion:"0.1.0",grantId:UUID,selectedMaterialConfirmed:true,
 selection:{purpose:"FINDING_EXPLANATION"|"PR_SUMMARY",scanJobId:UUID,
            reportSha256:sha256,prHeadRevisionId:UUID|null,
            findingIds:UUID[1..20],documentVersionIds:UUID[0..10]}}
```

selection 复用 `CreateAgentRequest` 语义：解释恰好1个Finding且PR=null；摘要1..20个且PR非null，须同一已完成扫描/报告和可信已应用PR修订。`selectedMaterialConfirmed` 是每次明确选材的非敏感/有权外发确认，不代替资源授权或新增数据字段；不得由页面加载提交。

201/重放200 `DailyRequestView={schemaVersion:"0.1.0",request:AgentRequestView,authorization:{grantId,riskAcknowledgementId,runtimeBindingDigest,settingsRevision},execution:{attemptId:UUID|null,accountingDay:date|null,costState:"NOT_ATTEMPTED"|"PENDING"|"SETTLED"|"UNKNOWN",reservedMicrousd:int64|null,actualMicrousd:int64|null}}`。沿用请求状态 `QUEUED|RUNNING|SUCCEEDED|FAILED`、Output和经过验证的引用。未产生 attempt 的费用为 null；SETTLED 的实际0才是可信零费用；UNKNOWN 和 PENDING 不显示0。QUEUED 仍可能尚未预留。

`GET /requests/{requestId}`、`GET /requests/lookup?idempotencyKey=<encoded-key>` →200同视图；lookup只查询当前owner/project的日常关联，请求键与旧 `agent.requests` 共享唯一域，任何跨模式碰撞均409。没有记录404，不按未知输入创建。lookup 固定路径应优先于 UUID 路由匹配。

`GET /requests?limit=20&cursor=<opaque>` → `{items:DailyRequestView[],nextCursor:string|null}`，limit=1..50，cursor最多512个base64url字符，解码为 `(createdAt,id)`；按二者降序键集分页，SQL始终限定当前owner/project与daily关联。cursor不能提供身份或扩大范围。可恢复服务器历史，无浏览器敏感结果缓存。列表/lookup/GET均不调度。

创建时先当前 owner/Project 授权及严格输入，再查询幂等历史；首次查询无记录时，按settings→所选grant usage取得串行锁后，必须再次按project/owner/key查询历史，且此复查先于当前grant可发送性和active槽检查。任一次查询找到记录，均比较已保存的规范化选择、grant和原绑定版本摘要；相同输入直接200返回已保存快照，**不重新检索/选“最新”文档、不重新调度**，不同输入409 IDEMPOTENCY_CONFLICT。历史 grant 已撤销/过期不妨碍有当前读取权限的恢复。只有锁后仍无历史的首次创建才执行全部当前发送前置校验、占逻辑槽并提交，afterCommit最多排队一次；插入唯一键冲突仍须读取胜者并按同一规则比较，覆盖不同grant锁域或模式的竞争。响应丢失后应先lookup/GET，不能生成新键规避未知结果。

### 4.5 稳定错误与角色

沿用既有 `ApiError`（`code`、`message`、`details`、`traceId`）与HTTP语义；400 INVALID_INPUT，401认证失败，403权限，404不可见资源，409 IDEMPOTENCY_CONFLICT/DAILY_STATE_INVALID/DAILY_ACTION_IN_PROGRESS，412设置修订冲突，428缺少If-Match，429 QUOTA_EXHAUSTED，503 MODEL_UNAVAILABLE。固定错误码 `DAILY_STATE_INVALID` 的message统一，不泄漏内部资源/配置；细分原因通过已授权context/grant读取。请求运行失败继续使用既有失败码（含OUTPUT_INVALID、CITATION_INVALID、AUTHORIZATION_REVOKED等）；本次不扩展旧Output错误Schema。

所有写入口执行现有凭据管理的 origin/secure/owner 防护；解释创建不能调用旧 `controls.authorizeWrite`，因其强制Maintainer，应复用其安全规则并单独 `requireViewer`。摘要另外 `requireMaintainer`。旧 `/agent/requests/{id}` 若命中日常关联也必须检查个人owner，防止通过旧GET旁路；旧synthetic/live读取语义保持。跨Project资源统一隐藏404，不能因daily状态先检查而泄漏资源存在性。

## 5. 不可变最小快照

从 `AgentApplicationService` 抽取最小的 `AuthorizedAgentSnapshotBuilder`，不移动请求持久化、审计或调度。精确接口：

```java
AuthorizedSelection authorize(UUID projectId, CreateAgentRequest selection);
AgentSnapshot build(AuthorizedSelection selection, SnapshotIdentity identity,
                    SnapshotProfile profile, String inputDigest);
record SnapshotIdentity(UUID requestId, UUID requesterId, String traceId, Instant createdAt) {}
record SnapshotProfile(String explanationPrompt, String summaryPrompt,
    String modelProfile, String protocol, String modelId, String priceVersion,
    boolean rejectWholeDocumentProjection) {}
```

`AuthorizedSelection` 为模块内部记录，包含已验证的ScanJobView、按UUID排序的FindingView、按UUID排序的DocumentVersionView、原purpose/PR选择等授权元数据；仅在新快照的build阶段检索并验证有界片段，确保旧请求重放先比较摘要且不读取Evidence或检索文档；不得公开到HTTP。授权查询仅走现有 `ProjectAuthorization`、`ScanJobOperations`、`FindingOperations`、`DocumentOperations`、`ReportSubmissionOperations`。ordinary synthetic传入原profile/false，日常传入现有DeepSeek profile/true；不是新增自由配置模型。

保留每Finding前20条直接Evidence、最多10条相关文档片段、单片≤1024字符、公开检索单次≤4条/4096字符及不透明随机alias。Evidence只发送kind两次及必要行号，绝不发送raw summary、路径、内部UUID；Finding只发送既有规则/版本/严重性/规范message/必要逻辑subject；文档只发送选定版本中有界相关excerpt/content hash，不发送文档名、整个版本或其他Project内容。选择文档不自动授权全篇：日常拒绝任何所选excerpt或同版本excerpt区间并集覆盖整个文档（即使原文很短），报400 INVALID_INPUT，零调用；不静默删除片段或放宽限制。文本仍可能有敏感内容，系统不能宣称过滤证明非敏感；owner明确选材责任继续成立。

业务幂等摘要使用固定顺序的JSON对象，固定域 `personal-project-agent-request-0.1.0`，包含 projectId、ownerId、grantId、该grant的runtimeBindingDigest、purpose、scanJobId/reportSha、PR修订、排序Finding IDs、排序文档版本/内容hash、Prompt/Schema/模型/协议/价格版本；不含随机alias和requestId。幂等重放使用已持久化文档绑定构建比较摘要，避免重检索。另在daily link保存完整model_input和candidates的字节规范化SHA-256，用于执行关联核验。

`LiveResourceAuthorizer.validate` 保持旧语义；新增 `validateDaily(AgentSnapshot)` 先执行原核验，再验证日常“非全篇”投影。它验证已保存片段，不替换快照；现有公开search仅在原版本/原查询下重放用于比对，不能重新生成输入或改alias。若检索算法变化不能重现旧片段，失败关闭。请求字段、当前资源归属、精确Evidence关系、文档内容/片段hash与范围在创建、领取/发送、结果保存、引用读取重新核验。正文从不成为审计内容。

全篇判定使用公开 `DocumentFragmentView.startOffset()` 和 `content().length()` 的Java UTF-16半开区间 `[startOffset,startOffset+length)`，对同一不可变版本合并重叠/相邻区间；并集覆盖 `[0,version.content().length())` 即拒绝，不能把UTF-8字节数当偏移。只计算真正选入输入的片段，已验证的片段hash/版本hash保存在原候选中；偏移由原公开检索重放验证，不新增正文或源码字段。

## 6. 最小执行复用接口

现有 `LiveExecutionCoordinator` 的HTTP、credential callback、截止期、独立settle、严格validator和结果事务算法复用一次；不复制另一条模型链。为去掉batch/template参数，增加仅Agent模块内部的两个窄接口：

```java
interface LiveExecutionLease {
    UUID projectId(); UUID requestId();
    LiveAccountingOperations.Admission reserve(LongSupplier remaining);
    LiveAccountingOperations.SendApproval checkBeforeSend(LongSupplier remaining);
    LiveAccountingOperations.Outcome settle(String priceVersion, LiveTokenUsage usage);
    LiveAccountingOperations.Outcome unknown();
    void stop(String code);
    void lockAndValidateSuccess(AgentSnapshot snapshot, LongSupplier remaining);
    void completeSuccess();
}
sealed interface LiveRequestBinding { UUID projectId(); UUID requestId(); Instant createdAt(); }
// SyntheticLiveBinding wraps the existing LiveRequestStore.Link;
// DailyLiveBinding wraps the new DailyAgentStore.RequestLink, with no template/batch fields.
interface LiveRequestAssociation {
    Optional<LiveRequestBinding> find(UUID projectId, UUID requestId);
    boolean claim(LiveRequestBinding exactBinding, UUID actorId, Instant at);
    void requireCurrent(LiveRequestBinding binding, AgentSnapshot snapshot, LongSupplier remaining);
    LiveExecutionLease lease(LiveRequestBinding binding);
    void stop(LiveRequestBinding binding, String code);
}
```

`SyntheticLiveRequestAssociation`仅包装旧links/会计/policy；`DailyLiveRequestAssociation`包装daily store/controls/accounting。`LiveRequestDispatcher`、`LiveDispatchTransitions`复用原可信身份/trace捕获、afterCommit排队、原始30秒预算、60秒队列年龄、精确CAS和claim失败所有权，内部改用关联接口。旧公开构造器/execute(project,batch,template,request)保留并委托synthetic适配，仍默认拒绝；新增接口/构造不成为公共发送入口。不能用null、全零UUID、requestId代替不存在的template/batch。

核心增加包内 `execute(LiveExecutionLease lease, LongSupplier remaining)`，核心内所有reserve/check/stop/settle/unknown改走lease，原外层重载只创建合成lease。同一个adapter发实际回复后先捕获并独立结算，消费者cleanup/输出/引用/撤权失败不能覆盖usage。失败所有权仍属于唯一claim/attempt胜者；重放没有终结原执行者的权利。

现有 `LiveResultTransitions.finishBounded` 先执行请求CAS，不能在它返回后另开事务释放日常槽。增加包内重载 `finishBounded(snapshot,result,usage,remaining,lease)`，在其唯一有界结果事务中依次执行 `lease.lockAndValidateSuccess` → 原结果CAS/审计 → CAS成功时 `lease.completeSuccess` → 原提交前期限检查。日常lease的第一步先锁settings→grant usage，再核对当前owner/用途角色、资源、grant/绑定/期限和SETTLED outcome；第二步只在同事务清除本请求占有的active槽，不新开事务、不更改次数/金额。合成lease这两个方法保持原行为的空操作。CAS未成功不得清槽；任何失败使结果、审计和槽释放一起回滚，已独立结算的费用不回滚。这样避免先锁requests再反向锁settings/grant。

`DailyAccountingService`提供 `reserve(project,request,remaining)`、`checkBeforeSend(project,request,remaining)`、`settle(project,request,price,usage)`、`unknown(project,request)`、`stop(project,request,code)`、`completeSuccess(project,request)`，返回现有内部 Admission/Approval/Outcome。settle/unknown/stop用 `LiveDatabaseWork.cleanup`，不依赖已失效的Project成员/设置/凭据来拒记已发生费用；只接受可信持久化请求/lease关联，不成为HTTP结算接口。

`DailyAgentOperations` 公共接口含 `context/settings/updateSettings/acknowledge/getRisk/revokeRisk/approveGrant/getGrant/revokeGrant/create/get/lookup/list`；使用第4节精确DTO（可作为该接口的public nested records）。再提供路由固定的 `authorizeSelectionWrite(project,origin,secure)`（owner+Viewer）和 `authorizeControlWrite(project,origin,secure)`（owner+Maintainer），供controller先授权后读正文；服务方法内部仍复核当前业务权限，摘要在解析用途后加Maintainer。对应 `DailyAgentController`、`DailyAgentControlService`、`DailyAgentRequestService`，由 `DailyAgentApplicationService` 实现公共接口并委托，不增加第二个同类型Spring bean。应用层持事务，构造器注入。新的 `PersonalDailyRuntimeConfiguration`复用 `LiveAdapterBundle`/`PersonalLiveExecutor`、fixed transport、VersionBoundCredentialUse、LiveDatabaseWork、LiveResultTransitions及AgentOutputValidator。两个模式共用同一受控executor和adapter生命周期，抽取单一 `PersonalLiveRuntimeResources` bean持有/关闭它们，避免两个runtime分别close同一bundle；原 `PersonalLiveRuntime` 门面不再声明第二个Spring destroy owner，兼容构造的单元测试仍可持有自己的独立资源。构造/关闭/页面读取不初始化网络。

`AgentRequestRouting.synthetic` 必须排除两种live关联；关联缺失或双重关联均失败关闭，不回退fake预算。已有 `AgentRecovery/AgentTransitions.recoverExpired` 对daily应转交 `DailyAgentRecovery`，不能先通用expire后漏记日常停发/UNKNOWN。

## 8. 事务、日界线与失败恢复

固定写锁序：`daily_project_settings → daily_grant_usage → live_budget_usage(DEPLOYMENT,day) → live_budget_usage(PROJECT,day) → agent.requests`。合成链原设置→batch→同部署日→同Project日顺序保持，不跨模式锁对方设置。纯CAS/读取不得拿request锁再反向申请设置/金额锁；排他link trigger只用于创建事务，创建尚不锁金额。

首次创建在一个有界事务中：当前owner/角色与strict输入→首次幂等历史查询→锁settings/所选grant usage（此时不先判grant有效性或active槽）→再次按project/owner/key读取幂等历史→无历史才检查当前grant可发送性及active槽→公开资源授权、投影和字节预检→重验期限/凭据/绑定→写requests+exact link+active指针+审计→提交后唯一调度。锁后查到胜者时，同键同原绑定输入直接200重放，同键不同输入409 IDEMPOTENCY_CONFLICT；两者都不重新检索或调度。只有真正不同键的另一逻辑请求占槽才409 DAILY_ACTION_IN_PROGRESS，未创建请求也不停grant。插入唯一键冲突保留读取胜者/比较输入的兜底，不靠活动槽错误代替幂等结果。

领取复用原精确CAS和可信OIDC/trace，提交后才调用核心。reserve在上述锁序下检查完整资源/关联、grant未撤销/停止/过期、当前settings revision、所有owner/运行绑定、用途与每次预留，锁后再检查。不存在attempt时同时增加grant attempts、grant和两层日额reserved、插入唯一daily_attempt及审计；已有同一attempt返回newAttempt=false。金额计算用减法避免溢出，所有次数/金额检查与写入同事务。

记账日为**首次成功预留的UTC日**。锁等待跨日则回滚、明确失败，不自动重试。checkBeforeSend必须当前UTC日等于attempt.day；跨午夜不得移预留到新日再发送。结算或UNKNOWN无论何时都只使用attempt存储的原day/deployment/价格。新一天可有独立技术日额，昨日UNKNOWN仍原样保留，不能移到新日重复扣款或清零；同日新grant/模式必须看到所有旧在途/UNKNOWN。grant累计金额/次数跨日一直保留。

费用和结果分别提交：可信usage按原绑定价格先写SETTLED，并将grant/原部署日/原Project日reserved减reservation、spent加actual，attempts不减；任何输出/引用失败、撤权、取消/关闭或超8,000输入观察阈值，仍保留该可信费用并停止grant。缺失/不可信usage、未知发送结果、崩溃保留UNKNOWN和reserved，停止grant。已有outcome返回原值；UNKNOWN不被迟到回包自动改写。人工账单更正若未来需要，另评审追加更正记录；当前无自动对账/账户探测/更正接口。

成功结果写入须在原deadline内、当前角色/资源/绑定/停止状态复核后完成，并在同一结果事务调用completeSuccess释放active槽。已SETTLED但结果提交失败或清理失败时槽继续阻止下一次调用；恢复只失败/停grant，不重发。费用结算不能靠result终态判断，更不能以grant已撤销为由丢弃本次处理中已收到的可信usage。

撤销与预留/发送复核共用settings→grant锁。最终SQL复核在凭据锁外，Key消费内只做既有同步身份能力/原剩余期限及一次send。保留现有事实：跨数据库授权与远程发送不存在原子“撤回”操作；复核后已经发出的内容无法撤回，撤销之后的收尾只记费/拒绝结果。不得增加持Key锁访问数据库造成锁序问题。HTTP期限、连接池/提交剩余限制沿用[数据库期限设计](v0.5-agent-database-deadlines.md)，不宣称绝对网络/供应商硬取消。

恢复：`DailyAgentRecovery.recoverExpired(snapshot,cutoff)`在有限cleanup中按同锁序重读状态/年龄。QUEUED无attempt→失败MODEL_TIMEOUT并停止grant，费用NOT_ATTEMPTED；RUNNING无attempt→明确未发失败并停grant；有attempt无outcome→追加UNKNOWN保留全部reserved并停grant；已有SETTLED→保留费用、只将未完成结果标失败并停grant。已终态不覆盖；所有路径不调度/不读Key。统一recover每轮仍≤100，按模式路由，不处理两遍。原synthetic/live恢复语义单独回归，不能借此大改历史恢复实现。

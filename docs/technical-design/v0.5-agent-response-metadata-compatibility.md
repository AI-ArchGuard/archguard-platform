# Agent v0.5 — 有界响应元数据兼容

范围：Platform #43 的独立离线增量。所有者于 2026-10-21 批准四个响应根字段的严格兼容，仅含离线实现与 CI，不授权部署、新真实请求、费用或恢复已停批次。既有失败的原始响应已丢弃，`RESPONSE_ENVELOPE / ENVELOPE_FIELDS` 只证明根对象形状或根字段白名单失败；不能推断实际字段、用量缺失或历史根因。本增量修补已离线复现的格式覆盖缺口，不宣称修复已验证的真实模型故障。

## 依据与方案

继承 Docs ADR-0010 至 ADR-0015 和[个人接入设计](v0.5-agent-personal-deepseek.md)的逐字段兼容白名单。DeepSeek [Responses 指南](https://api-docs.deepseek.com/guides/responses_api/#response-fields)指向完整 Responses 响应格式；OpenAI [Responses retrieve 的根 Schema 与示例](https://developers.openai.com/api/reference/python/resources/responses/methods/retrieve)定义了这四个可空字段。该参考不证明 DeepSeek 实际返回任何特定字段、实现全部能力、保存期限或模型不可变性。

保持当前全部拒绝会继续拒绝已知的惰性元数据；忽略任意未知字段会丢失信任边界。选择只增加以下四个根字段并逐值验证，不新增依赖、SDK、公开 DTO、Schema 或数据库迁移：

- `user`、`max_tool_calls`：允许缺省或 JSON `null`；拒绝其他全部类型和值，包括空串、零、空对象和空数组。
- `top_logprobs`：允许缺省、JSON `null` 或 JSON 整数 `0`；拒绝浮点/指数形式的零、字符串、非零和其他类型。输出内容的 `logprobs` 仍必须缺省或空数组。
- `completed_at`：允许缺省或 JSON `null`；非空时只能是整数 Unix 秒，范围 `0..253402300799`（含端点），且必须存在相同类型和范围的非空 `created_at`，满足 `completed_at >= created_at`。

整数秒、公元 9999 年末上界及创建/完成时间比较是实现方在已批准“有界、非负、不早于创建”范围内选择的本地规则，不声称是官方强制要求。使用 Jackson 的 `isIntegralNumber`、`canConvertToLong` 后再比较 `long`，不截断或强制转换字符串/小数，不使用浮点数或本机时钟。完成时间缺省/null 时，保留原先 `created_at` 的行为，不增加缺省值、不新增必填或验证。

## 信任与费用边界

仅在根白名单增加四个固定名称，并在用量校验之前验证以上规则。非法已知元数据使用固定内部 `ENVELOPE_METADATA / RESPONSE_ENVELOPE` 原因，公开仍是 `OUTPUT_INVALID`，不提供可信用量；本格式兼容增量当时对未知根字段/非对象共同使用 `ENVELOPE_FIELDS`。后续 2026-10-23 获批的[脱敏诊断细分](v0.5-agent-safe-response-diagnostics.md)仅将二者区分为 `ENVELOPE_UNKNOWN_FIELDS`/`ENVELOPE_NOT_OBJECT`，并为前者增加饱和于 32 的根未知字段整数数量；不扩大此处白名单或接受范围。历史日志不改写，仍不记录字段名、字段值、响应正文、凭据、解析器异常或 cause。

其他未知字段（包括 `access_programs`、`conversation`、`prompt`、缓存策略等）仍拒绝；四个名称不能进入 usage/details/message/content 白名单。原有模型、状态、标识、`store`、工具、后台、会话、重复键、尾随 JSON、64 KiB、Token/费用及业务输出/引用检查不放宽，也不趁机加强与此无关的兼容字段。请求投影八个固定字段不变，不向提供方发送新增字段。元数据不进入业务结果、日志或审计；既有内部解析封装只存活于本次解析。

可信用量和业务输出独立：合法元数据+可信用量+不合格业务内容仍返回可信用量供原执行核心结算；元数据或用量不可信则保持 UNKNOWN、预留和停批，不推断零费用。无重试、字节清理、trace 隔离及三层额度语义不变。不改写旧请求、确认、批次、迁移或凭据。

先对旧实现运行新测试并观察失败，再做最小实现。手写独立合成封装覆盖缺省/null/允许组合、零与上界、时间先后、类型/范围/溢出/精度拒绝、重复四字段、未知字段并存及错误嵌套。客户端测试仅注入假 exchange：成功保持业务文本/用量且无拒绝日志；元数据失败单次交换、响应字节清理、公开脱敏错误和唯一固定诊断；业务失败保留已知用量。全部原有测试和完整 Maven verify 继续执行，不能删测或降低断言。
